真实推理及渲染测试需要本地模型、素材和录像。修改推理时核对帧覆盖、原始 PTS、时序窗口、检测证据与回合边界；修改呈现时核对完整解码、帧数、音画时间、源画面／原声内容和标题字形。安装包还需仓库外导入验证，不能仅在源码路径中测试。

详细脚本清单见 [scripts/README.md](../scripts/README.md)，项目贡献约定见 [CONTRIBUTING.md](../CONTRIBUTING.md)。测试数量随代码变化，以当前输出为准，不把历史“某次通过多少项”当作持续保证。

核心数据链路是 `match_manifest.json → edit_decision.json → replay_reviews.json → render_report*.json → verification*.json`。CLI 退出成功、分析完整、渲染完成和内容正确分别判断。空事件、超时、非法 JSON、证据缺失不能合并统计成成功；缓存复用要与新请求、新推理分开计时。

## 性能与四卡分析

共享推理只解码一次。四卡按模型分工：状态、动作、人物、球轨迹及辅助球检测，保留每个时序模型的连续历史，不将录像硬切成四份。开启号码识别时 OCR 使用人物卡。编码仍为 CPU `libx264`。

```bash
volleymole run --video data/match.mp4 --top-k 5 --ranker rules \
  --devices cuda:0,cuda:1,cuda:2,cuda:3 --pipeline-depth 2 \
  --auxiliary-device cuda:0 --vball-engine ort-bound \
  --preview-workers 2 --render-workers 2 \
  --no-analysis-cache --output runs/performance-new
```

`--devices` 要求四张不同且可用的卡，不能与单卡 `--device`、独立推理或显式历史证据导入混用。`pipeline-depth` 默认 1，可用 2–4 增加在途批次；更大值占用更多内存。`ort-bound` 是 ONNX Runtime CUDA 的 I/O Binding，不是 TensorRT 或 INT8；不保证所有负载都更快。

`preview-scope needed` 默认只为真正需要的候选生成截图；规则模式先用同一选择函数确定入选项，API 模式为实际候选池抽图。`render-workers` 默认 1、最多 4，仅并行独立片段；有依赖的转场和最终合成保持顺序。

历史实测（2026-09-10，四张 RTX 3090，同源 57,531 帧）：

| 范围 | 结果 | 边界 |
| --- | --- | --- |
| 单卡与四卡，从输入到回合清单 | 1048.111 秒 → 615.642 秒，约 1.702 倍 | 单次历史对照、有其他进程，不包括排名、渲染、验收 |
| 优化后的规则五佳全流程 | 638.290 秒，成片 170.5 秒 | 无分析缓存；含分析、规则排名、渲染与验收，不含语义 API |
| 其中共享分析／渲染／验证 | 463.894／109.873／42.103 秒 | 同一连续运行的阶段墙钟，不能挪作其他素材的承诺 |
| 按需预览 | 624 张减为所需 15 张，耗时 1.515 秒 | 比较的是该次五佳任务，不代表所有任务同样收益 |

对应原始证据与边界的一致性已经做过对照；自动结果一致不代表识别准确。模型线程计时有重叠，不能相加当总耗时；设备总显存可能含其他进程。原记录位于 `runs/four-gpu/`、`runs/optimization/full-optimized/`。

复现时使用新目录并关闭分析缓存：

```bash
python scripts/benchmark_optimizations.py --video data/match.mp4 \
  --output runs/benchmark-new --max-frames 1802
python scripts/benchmark_render.py --reference runs/my-match --output runs/render-benchmark-new
python scripts/compare_optimized_run.py --reference runs/reference --candidate runs/candidate
```

保留短尾、帧覆盖和完整验证；短测不代表整场倍数，没有同硬件重复样本时不报告中位数或 P95。

## 公开数据与适用范围

以下是项目截至 2026-09-12 的取得与评测状态，不代表重新在线核验了最新数据。来源、逐文件校验和许可保存在对应本地 manifest 中。

| 数据 | 已取得／已执行 | 可以评价 | 不能代替 |
| --- | --- | --- | --- |
| [VNL-STES](https://hoangqnguyen.github.io/stes/) | 原标签、选定连续 JPEG，原 train 48／val 6／封存 test 6 条适配实验 | 六类动作的类别与时间定位 | 精彩度、趣味度、完整回合边界、笑声关联 |
| [ESC-50](https://github.com/karolpiczak/ESC-50) | 全部 2,000 音频及原类别，完成声音评测 | 笑声、掌声的片段分类 | 强时间定位、邻场归属、画面关联 |
| [FSD50K](https://zenodo.org/records/4060432) | 原 dev/train 固定 236 段，排除 ESC 源 ID，用于阈值校准 | 候选阈值开发拟合 | 独立泛化测试；eval 音频尚未评测 |
| [SVHighlights](https://github.com/leedongkyu2019/SVHighlights) | 40 场官方集锦对齐标签与原音量特征，跑过音量基线 | 官方编辑偏好的时间段代理指标 | VolleyMole 全流程成绩、五大囧、剪辑完整性 |

VNL 原数据是 25 FPS 连续 JPEG，无音轨、无原整场时间偏移。派生视频不插帧、不造声音、不改标签，实际分辨率为准，不能从文件名推断 1080p。公开归档各 split 按比赛隔离，保留 `events`、声明计数和实际帧数差异，不混用 `all.json` 与测试 split。代码许可证不能套用于比赛素材。

其他来源中，VREN 仅取得动作表、不能匹配视频；RIT-18 和 RallyTrack 未取得可用素材；Ibrahim Volleyball 局部窗口与 Oops! 通用意外标签不能当作排球趣味真值。

### 训练、开发与测试隔离

按整场比赛 ID 隔离，同场不同片段不能跨分区。训练只读 train；早停、阈值、NMS、提示词等只用 val/dev 调整。封存 test 排除已查看样例，冻结模型、参数和代码后再评测；失败请求保留漏检，不移除以提高分数。原标签不被模型伪标签替代。

```bash
python scripts/acquire_volleyball_benchmark.py --split val --sample-count 6 \
  --prepared-name val_development --direct
python scripts/acquire_volleyball_benchmark.py --split train --samples-per-match 8 \
  --prepared-name train_adaptation --direct
python scripts/acquire_volleyball_benchmark.py --split test --sample-count 6 \
  --prepared-name test_final_sealed --sealed \
  --exclude-manifest data/public_benchmarks/volleyball/vnl_stes/manifest.json --direct
```

重试不能换失败 ID；保留整个 `vnl_stes/` 目录及其相对链接，不能只迁移 prepared 子目录。五例早期诊断与后来的六例封存测试属于不同样本，不混算成绩。

<a id="action-model"></a>

## 本地动作模型与准确性

本项目实验采用冻结 ImageNet **ResNet18＋双层双向 GRU**：保留 398×224 全图、全局与 2×3 空间池化，按原 25 FPS 做六类多标签预测。它是小样本适配实验，不是 VNL-STES 作者模型复现；当时未取得可用排球 checkpoint，没有将论文成绩当成本地成绩。

```bash
python scripts/train_action_spotter.py --device cuda:3 train \
  --train-manifest data/public_benchmarks/volleyball/vnl_stes/prepared/train_adaptation/manifest.json \
  --val-manifest data/public_benchmarks/volleyball/vnl_stes/prepared/val_development/manifest.json
python scripts/export_action_evidence.py data/match.mp4 \
  --output runs/action-evidence-new.json --device cuda:3 --total-timeout 300 --max-cache-mib 2048
```

导出绑定原片 SHA、真实 PTS、模型和配置，仅支持满足实际 25 FPS 的源视频；其他帧率返回 `unsupported`，预算不足返回 `partial`，不伪造完整覆盖。以 `--action-evidence` 或 `--action-evidence-dir` 显式接入事件路线，候选仍需复核，未设为默认生产模型。

2026-09-12 封存六例、35 个原事件，F1 使用类别内 0.5 秒容差的一对一匹配：

| 方法 | Precision | Recall | F1@0.5s |
| --- | ---: | ---: | ---: |
| Qwen3-VL-8B，原 2 FPS 诊断基线 | 13.16% | 28.57% | 18.02% |
| 本地 ResNet18＋GRU | 25.00% | 45.71% | 32.32% |
| 既有 YOLO 检测器 | 40.00% | 5.71% | 10.00% |

本地模型相对既有检测器有改善，但误报和漏检仍多，且测试只来自一场比赛，不能声称跨比赛可靠。旧 YOLO 上游训练数据来源不透明，不能宣称与公开数据完全无重叠。详细分类结果在 `runs/action_accuracy/`；实现为 [action_spotting.py](../src/volleymole/action_spotting.py)。

历史密集 8 FPS 的小样本实验没有证明动作准确性改善，部分请求失败或零事件。生产协议通过、图像输入兼容和动作理解准确是不同结论。

## 声音模型部署与评测

使用作者预训练的 **PANNs Cnn14_DecisionLevelMax**，本项目没有重新训练声音网络。普通 clipwise Cnn14 不能替代 framewise 接口。运行时输入为 32 kHz 单声道，输出为带时间的类别概率；10 ms 输出由约 320 ms 的 CNN 决策插值得到，不能当作精确触球时刻。

```bash
python scripts/install_sound_model.py
python scripts/prepare_public_audio.py --help
python scripts/evaluate_sound_events.py --help
python scripts/prepare_sound_calibration.py --workers 8 --mirror
python scripts/calibrate_sound_thresholds.py --device cuda:0
```

安装后产生 `models/audio/panns_cnn14_sed.pt`、`.labels.json`，**在事件路线且非规则排名时**发现这对文件才自动启用。`--no-sound-model` 关闭；`--sound-model` 与 `--sound-labels` 可显式指定，`--sound-device` 默认 CPU。阈值侧文件 `.thresholds.json` 绑定模型与标签哈希，未设置类别使用 0.5；运行不联网下载。

安装器检查官方权重哈希、严格载入参数并导出 TorchScript。代码改编与权重许可分别保留，来源见 [PANNs 作者代码](https://github.com/qiuqiangkong/audioset_tagging_cnn) 和[权重发布](https://zenodo.org/records/3987831)。15 组声音及长度与作者原实现的数值对照曾得到最大误差 0，这只证明实现一致。

历史评测结论：

- ESC-50 全量 2,000 条完成，基线笑声 AP 0.6851、掌声 AP 0.9243，但默认 0.5 阈值仅检出 1/40、0/40。
- FSD50K 的 236 条独立 dev/train 样本按固定原标签选 F2 最优阈值，未重新训练网络。开发集拟合结果不是独立测试。
- 固定阈值复用已看过的 ESC 预测后，两类各检出 40/40，但名义负例分歧为 77/1,960、68/1,960，精确率仅 34.2%、37.0%。这是非盲后续检查，候选覆盖改善伴随误报。
- 无强时间或画面关联真值，不能从这些结果推出得分、触球、邻场归属或趣味事件准确率。

完整阈值、原数据许可和校验保留在模型与数据 manifest，报告位于 `runs/public_benchmarks/`。声音分数只提供待复核证据。

## 精彩与趣味评测

### 官方集锦代理

SVHighlights 的 40 场原音量基线宏平均 AP 为 12.0116%、Hit1 为 30%、HitK 为 15.1576%。**这些不是 VolleyMole 的成绩**；当时没有下载并运行 40 场完整转播流程。标准非插值 AP 也不是作者 HL-mAP，不能混用。

```bash
python scripts/evaluate_svhighlights.py --loudness-baseline --output runs/sv-volume-new.json
python scripts/evaluate_svhighlights.py --predictions predictions.json \
  --model-name my_model --output runs/sv-model-new.json
```

预测可用逐 bin 分数（`vid`、`pred_saliency_scores`），必须严格对应原裁切视频的 2 秒 bin；也可用区间与明确 `time_basis: source|trimmed`、`background_score`。source 时间由 manifest 偏移转换，半开区间映射取重叠事件最大分。默认要求全部 40 场，子集需 `--allow-subset` 并报告缺失；不补零修复错位长度。

### 独立趣味评分

`scripts/blooper_benchmark.py` 已实现候选导入、匿名原速素材、空表与离线页面、评分校验和指标；**尚无足以证明五大囧质量的独立真人评分集**。空表结果是未知，不是 0 分或准确率。自动标注、笑声和普通失误标签不能替代真人趣味判断。

保留以下评测约束：

1. 以完整“铺垫—意外—反应”为单位，按比赛划分开发／测试；素材不加慢放、配音或解释包装。
2. 候选并集、独立时间抽样、全场人工巡检分开记录；只有最后一种才能提供全场召回参照。
3. 每事件、每条件至少 3 位独立真人；有声与去声版本使用不同评员组，隐藏模型、排名与他人答案。
4. 先记录事实和边界，再独立评价总体有趣度与入选适合度，最后评价分析维度。整数 0–4，未知填 null；不由模型权重公式推导总体分。
5. 至少 3 个已知总体分才形成中位数参照；保留分歧。静音时笑声相关字段为 null，模型标签不得冒充 `human_only`。
6. 指标包括前五质量、适合比例、风险比例、评审池 nDCG@5 和序数 Krippendorff α；同时报告返回数量、缺失参照与比赛覆盖。
7. 比较需相同比赛、条件与完整参照。按比赛等权汇总，至少 10 场已知指标才提供 2,000 次比赛级 bootstrap 区间；这是工程约定，不保证泛化。仲裁不自动覆盖原始评分。

完整字段量表与校验以 [blooper_benchmark.py](../src/volleymole/blooper_benchmark.py) 的生成表和实现为准。流程为 `import-timeline → prepare → render → pages → evaluate`，各步参数见 `python scripts/blooper_benchmark.py <步骤> --help`。只收集每人唯一最终表，私有映射不发给评员，空表只能检查管道。

最初六条自动视觉初筛只看少量帧，没有确认可入榜片段，不能作为独立准确率。原记录保存在 `runs/auto_bloopers_10min/`。没有完整人评、叙事边界与多场端到端计时时，不报告前五质量、解释正确率或 P95 已达标。
