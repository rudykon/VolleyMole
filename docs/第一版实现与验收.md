# VolleyMole 第一版实现与验收

日期：2026-09-09。源码入口：`tools/volleyball-top-plays/run_match.py`。

## 已实现

顺序运行比赛分析、球追踪、可选号码识别、回合分割、关键帧导出、规则预筛、大模型 JSON 决策、本地校验、竖屏渲染和完整解码检查。各上游在独立环境中通过子进程调用；不建设多智能体，不训练模型。

全片时间以显示时间戳为准。动作检测按时间聚合成事件，不能把逐帧框数量当独立动作数。静止持球不参与空中运动打分，参与人数降低热身片段的优先级。号码需要至少两个高置信度样本才提升权重。未入选候选保留明确原因。

输出为 720×1280、30 fps 的 H.264/AAC，排名倒计时，跟球细节画面下保留全场小画面。源视频静音时补静音轨；轨迹没有可用采样时居中构图。

## 大模型接入状态

已读取本机 `llm_api.json` 的 `llm` 节点：GLM-5.2，OpenAI 兼容接口。无图文本连通性请求返回 HTTP 200；独立 JSON Schema 格式测试也返回 HTTP 200、`finish_reason=stop` 和合法 JSON，消耗 391 tokens。该格式测试没有发送任何比赛信息。`rank` 节点的 `bge-reranker` 不用于生成剪辑单。

用户随后明确授权上传。真实截图测试显示 GLM-5.2 返回 HTTP 400：`not a multimodal model`；同一服务的 Kimi-K3 和 Qwen3.8-27B 均返回 HTTP 200、正常结束的 JSON，并正确描述了排球画面中的低位接球场景。因此已接入“视觉模型分批评审 → GLM-5.2 综合排序”的自动路由，保持主排序模型不变。

完整语义流程现已实测成功：Qwen3.8-27B 分 25 次评审 25 个候选的 75 张关键帧，全部输出合法 JSON；随后 GLM-5.2 综合排序，返回合法五佳剪辑单。运行模式为 `vision_then_text_api`，`fallback` 为 `null`。这 26 次成功请求共记录 68,444 tokens（视觉 53,867，最终排序 14,577），不含此前连通性探测及失败请求。完整结果保存在 `semantic/batch_01.json` 至 `batch_25.json`、`edit_decision.json` 和 `ranking_log.json`。

最初 Kimi-K3 的五回合／15 张图请求在 240 秒后超时并正确降级。改为已验证的 Qwen3.8-27B，每次仅评审一回合三张图后，完整视觉与排序阶段在约 691 秒内成功。成功批次具有独立输入指纹，重试不必重复已完成的视觉评审。API 返回不符合本地约束时仍自动使用规则排序，并保存失败类别。

原规则版另保留为 `top5_rules.mp4` 与 `edit_decision_rules.json`，时长 140.5 秒；它不是本次语义评审输出。

## 质量范围

最终语义五佳来自原片约 10:59、17:09、25:18、25:46、28:10，包含三个较长攻防回合和两个低位防守片段。已通过时间序列截图检查连续攻防和结束上下文；这不等于建立了全场人工回合真值，也不应报告正式识别准确率或召回率。低球、出画、遮挡、休息与热身仍可能影响候选边界，所有统计和动作标签保留为模型证据。

上游 `make_reels.py` 原版的名义帧率导出和无音频输出不适合直接作为最终成片。本实现复用其平滑、裁剪函数，并以源 PTS 重新解码和封装音频；合并时按各段精确长度拼接音视频，避免 MP4/AAC 时长取整积累。
