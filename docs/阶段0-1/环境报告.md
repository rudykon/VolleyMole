## 发现的问题与修复

1. **问题**：`onnxruntime 1.24.1` 创建 `CUDAExecutionProvider` 失败：
   `libcudnn.so.9: cannot open shared object file`，随后**静默回退 CPU**。
   这正是合同禁止的失败模式（实施方案 §1：失败须明确报错，不静默降级）。
2. **修复**：在上游固定仓库 `.venv`（Python 3.12.3，uv 管理）安装
   `nvidia-cudnn-cu12==9.25.1.1`（连带 `nvidia-cublas-cu12==12.9.2.10`、
   `nvidia-cuda-nvrtc-cu12==12.9.86`），安装源：清华镜像
   （pypi.org 经本机代理不可达，已验证）。
3. **生效方式**：运行前导出
   `LD_LIBRARY_PATH=<venv>/lib/python3.12/site-packages/nvidia/cudnn/lib:.../nvidia/cublas/lib`。
   阶段 1 引擎在进程内以 `ctypes.CDLL(..., RTLD_GLOBAL)` 预加载 cuDNN/cuBLAS，
   不再依赖调用方环境变量。
4. **防静默回退**：引擎预检创建会话后断言
   `"CUDAExecutionProvider" in session.get_providers()`，否则抛出结构化错误
   `EngineError(GPU_UNAVAILABLE)`；上游脚本本身允许回退，基线复现运行时由
   包装脚本校验并记录实际 providers。
