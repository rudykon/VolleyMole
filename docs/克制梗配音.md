# 克制梗配音

`meme-audio` 给已完成的剪辑添加短配音。默认最多两处，画面编码和每个视频包的时间戳保持不变；现场声只在配音期间短暂降低，并渐入渐出。它不增加分屏、贴图、插片或片长。

```bash
.venv/bin/volleymole meme-audio \
  --video outputs/approved.mp4 \
  --plan data/meme-plan.json \
  --output outputs/with-memes.mp4
```

计划中的素材路径相对计划文件解析，只读取本地文件：

```json
{
  "version": 1,
  "max_cues": 2,
  "selection_mode": "explicit_editorial_times",
  "cues": [
    {
      "id": "nice",
      "asset": "meme-assets/nice.wav",
      "at_sec": 12.5,
      "source_start_sec": 0.0,
      "source_end_sec": 0.9,
      "rms_db": -20,
      "duck_db": -3
    }
  ]
}
```

`at_sec` 是成片时间；`source_start_sec` / `source_end_sec` 是原声素材内的完整短句区间。`rms_db` 控制配音电平，`duck_db` 控制配音期间现场声降低多少。应给动作的前后留出空间，避免盖住触球声；这里的淡入淡出不替代完整语句边界的选择。

处理前拒绝超出密度上限、重叠、越过成片结尾或素材长度不足的配音，不会把一句话强行截断。单次素材限 0.1–5 秒。默认最多两处；确需更高密度时可显式设置 `max_cues`。已有输出和报告不会被覆盖。

输出旁的 `.audio.json` 保存原片、素材、计划与成片的 SHA-256、插入时间、实际增益和画面完整性检查。配音电平先按 RMS 归一化并限制峰值，再根据现场声余量降低增益；源音过响且无法在该位置安全混合时停止。输出 AAC 应另查实际峰值和听感。

`meme-audio` 本身只负责离线混音；现在可由 `meme-director` 调用视觉大模型自动选择梗与时间，再生成它读取的计划。13 个梗的条件、API 流程和当前验证范围见[梗使用条件与 API 导演](梗使用条件与API导演.md)。

允许计划包含零条配音：模型判断不合适时直接复制原片，音视频均不重新编码。添加配音后的文件使用独立名称和音频检查报告，不能当作原声未修改的主剪辑来验收。

第三方原声素材保存在用户自己的 `data/` 下，不包含在项目的插画素材包或源码分发中。
