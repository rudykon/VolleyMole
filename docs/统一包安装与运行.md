# VolleyMole 统一包安装与运行

核心整合、整场共享分析和回合证据回归均已通过阶段门槛；最终验收状态见
[单仓库整合实施与验收](单仓库整合实施与验收.md)。旧入口只转发到统一包，
不再调用上游源码或独立虚拟环境。历史实现已冻结在本机基线归档中。

本机最终总验收已通过并单列限制：60 项新版测试、33 项旧入口兼容测试，真实语义五佳、
HTTP 503 降级十佳、恢复和音画/透明标题检查均完成。原始试验记录不随安装包分发。

## 安装

本次锁定目标为 Linux x86-64、Python 3.12、FFmpeg/FFprobe，CUDA 推理使用
支持本机 RTX 3090 的驱动。应用不安装或修改显卡驱动。CPU 也可运行；
当前统一锁包含 GPU 库，尚未另做精简 CPU 发行版。

```bash
uv sync --locked
.venv/bin/volleymole --help
```

锁文件固定 PyTorch 2.11.0 / torchvision 0.26.0 的 CUDA 12.8 发行包，
让 ONNX Runtime 与 PyTorch 共用同一 CUDA/cuDNN 主版本，依据
[ORT 的兼容说明](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html#compatibility-with-pytorch)
和 [PyTorch 对应发行包](https://pytorch.org/get-started/previous-versions/#v2110)。
只安装 `opencv-python-headless`，不让两个提供 `cv2` 的 wheel 相互覆盖；
通过 [uv 的 exclude-dependencies](https://docs.astral.sh/uv/reference/settings/#exclude-dependencies)
排除 Ultralytics 间接声明的 GUI wheel。应使用提供的 uv 锁安装，
而非直接让无锁 `pip install .` 重解出另一套依赖。

## 模型：先获取与校验，再离线推理

```bash
.venv/bin/volleymole models --directory models fetch
.venv/bin/volleymole models --directory models verify
```

下载使用固定公开地址，既不读取 API 密钥也不上传素材。安装 `curl` 时优先使用
其 HTTPS 传输（有限重试、传输时间及文件大小上限），否则使用 Python urllib。
某个地址不可访问
时会失败，不自动改用来源未知的镜像。也可导入已合法取得的对应文件：

```bash
.venv/bin/volleymole models --directory models import-file vball /path/to/VballNetV1_seq9_grayscale_330_h288_w512.onnx
```

各 ID 和预期 SHA-256 见 `src/volleymole/model_manifest.json`。哈希/大小不符
不会替换现有模型。可用 `--models /absolute/model-store` 或
`VOLLEYMOLE_MODELS` 选择位置；默认当前工作目录的 `models/`。
获取模型后，运行时不需要三个外部源码目录、它们的虚拟环境或自动下载器。
权重的许可边界见 [THIRD_PARTY.md](../THIRD_PARTY.md)。

## 单命令

```bash
.venv/bin/volleymole run --video data/样例视频/1.mp4 --top-k 5 --models models --device cuda:0
.venv/bin/volleymole run --video match.mp4 --top-k 10 --ranker rules --focus-player 12
```

本机配置的 GLM 曾多次在最终排名超时。已验证可用的同服务替代路径如下，
仅通过参数覆盖这次运行，不修改配置文件：

```bash
.venv/bin/volleymole run --video data/样例视频/1.mp4 --top-k 5 --device cuda:0 \
  --model Qwen3.8-27B --vision-model Qwen3.8-27B --api-timeout 360 \
  --output runs/integration/final-qwen-top5
```

不指定号码时不会启动 OCR。默认 `--style lively` 保留 5 秒快切、3 秒转场、
中文第几球、项目标志、短慢回放、原声与透明回合标题。`--font` 可替换中文字体。
当前渲染仍使用 CPU `libx264`，`--device` 指的是神经网络推理设备，
不表示成片自动使用四张 GPU。

默认 `fused_v2` 回合算法增加低球与实际辅助检测关联。辅助检测至少需两帧、
有前后 VballNet 锚点且满足位置/速度限制；低球需场内人体范围和状态/附近动作支持，
排除随人体一起移动的疑似持球。短暂缺失只标为不确定遮挡，不补造检测坐标；
渲染时的裁切中心仍可以平滑插值，两者不能混同。
新增证据不能抹掉两个较强空中运动区间原有的分隔；中点边界仍明确是保守假设。
`match_manifest.json` 和逐回合轨迹保留来源、不确定性和原始 CSV 路径。
可通过配置 `{"rally_algorithm":"legacy_v1"}` 对照旧算法。

大模型沿用 `llm_api.json` 的 `llm` 节点或 `VOLLEYMOLE_*` 环境变量。
规则模式不发 API 请求。缺失配置、连接失败或非法剪辑单按规则降级，
原始失败类别保留；不把规则结果称为语义模型结果。

发给模型的是有界证据摘要（关联数量、少量示例、最长的几个遮挡区间），完整逐帧信息
仍保存在清单中。视觉缓存以完整候选、原截图、模型和提示词判等，已成功的同证据评审
可以复用。接口负载会影响耗时；最终文本排名仍可能超时。可用
`--rerun-from rank --api-timeout 300` 重试，复用已完成的视觉批次。
排名报告内复用批次的 token 用量是历史请求用量，不能当作本次新增消耗。
最终生成设置 8192 输出 token 上限；被截断、拒绝或不是合法 JSON 的响应不会进入剪辑。
`fallback.response_contract` 和 `finish_reason` 在相应失败时给出安全分类，不保存远程错误正文。

重复同一命令时，成功阶段须通过输入/输出哈希校验才复用；失败阶段重试。
默认 `--inference-mode shared` 在分析阶段只解码一遍，号码模块复用人体检测，
额外球检测按缺失证据触发。原独立模块可用 `--inference-mode independent` 对照。
共享分析缓存默认放在 `runs/.analysis-cache/<内容指纹>/`，与 top-k、标题样式、
API 排名分离，所以同源的五佳/十佳可复用检测。模型、代码、精度、实际后端、
号码配置和依赖版本参与指纹；更换素材内容或改变相关设置即失效。
可用 `--analysis-cache-dir` 改位置，`--no-analysis-cache` 强制重算。
`inference_cache.json` 保存计数与历史遥测，当前命令是否实际推理另记入计时报告。
也可以 `--rerun-from rank` / `render` 指定重做起点。输出与实际命令耗时
仍在 `runs/<素材名>-topK/`，使用 `--output` 可选择其他目录。

## 基线对照入口

新入口不自动扫描外部项目。显式复用旧的完整 VolleyMole 证据时：

```bash
.venv/bin/volleymole run --video data/样例视频/1.mp4 --top-k 5 --ranker rules \
  --evidence-cache runs/1-top5 --output runs/integration/package-parity-top5
```

缓存必须包含完整 manifest、源文件哈希及检测证据；逐帧 PTS 和覆盖校验仍执行。
报告明确标记旧证据导入，不能把这类命令的时间当作新模型整场推理性能。
`infer --max-frames` 的局部烟测输出明确标记 `partial_smoke`，不得导入为整场缓存。

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/volleymole infer --kind analytics --video data/样例视频/1.mp4 \
  --output runs/integration/smoke-analytics --device cuda:0 --max-frames 90 --half
.venv/bin/volleymole verify --run runs/integration/package-parity-top5
```

完整基线快照位于 `runs/integration/baseline-20260910/`（不提交 Git）。
阶段门槛未全部通过前，不删除上游目录或替换用户的旧成片。

## 已实测的限制

- 本机 9 个所需权重/配置均通过 SHA-256，CPU/GPU 和仓库外安装包实跑通过。
- 公开小型 VballNet 下载成功。Drive 核心包、人体和 OCR 识别模型的远程重验
  遇到 TLS 或传输截断，不能声称所有权重在线获取已通过；下载失败不会覆盖现有模型。
  网络不可用时可逐个 `import-file` 导入已合法取得的精确权重。
- 本机真实比赛没有可靠可见号码，未证明真实球衣号码准确率；实际 OCR 模型仅在
  另行标记的合成数字样本中完成阳性验证。远景、多人/多球热身与遮挡仍需人工抽查。
- 规则十佳抽查发现第八球（原片约 44–62.25 秒）包含多球热身，说明规则分数还不能可靠
  区分热身与正式对抗。保留该降级回归结果和证据，不将其宣称为完美的十佳语义选择。
  规则模式的回放点来自动作检测或候选中点，不保证是整段最精彩动作，也不表示经过视觉 API 评审。
- 完整比赛对照使用旧自动候选，不是人工真值；没有独立标注集，不能给出召回率或胜负准确率。
- 本次锁仅实测 Linux x86-64、Python 3.12 和本机 RTX 3090；其他系统、驱动和精简 CPU 安装未验收。
