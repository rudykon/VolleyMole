# VolleyMole 单仓库整合：实施与验收台账

本轮目标以用户的单仓库整合要求为准，取代第一版“运行前手工准备三个外部源码目录”的部署约束。保留单场视频五佳／十佳范围，不扩展比分、直播、多机位或训练平台。

最终状态（2026-09-10）：单仓库实现及约定的本机回归完成。总审计为
`runs/integration/final-integration-audit.json`，状态 `passed_with_documented_limits`。
在线权重下载、默认 GLM 的历史超时、真实号码准确率与热身误选限制在下文单列，未标为通过。

## 顺序与门槛

1. **基线**：冻结当前工作树（包括未提交的透明标题样式）、环境版本、模型/素材哈希、真实五佳成片和实际校验。历史四卡推理、当前缓存成片、重新执行的检查分别记账。
2. **核心模块整合**：建立可安装的 `volleymole` Python 包与单命令入口；引入有明确 MIT 许可的独立 `volleyball-ml-models` 核心和 VballNet 必要逻辑；号码识别自行实现。保留语义排名、PTS 跟球竖屏、声音、回放、断点恢复与现有测试。通过隔离运行、权重校验、实际 CPU/GPU 烟测后进入下一阶段。
3. **共享解码与检测**：统一源 PTS 帧结构、模型配置和内容寻址缓存；同一解码流供状态、动作、球追踪和号码模块使用，人体检测只做一次。VballNet 为主要球证据，额外球检测有明确触发条件及调用计数。比较独立模块与共享流程的时间轴、检测证据、耗时和显存。
4. **回合质量**：利用低位运动、动作、人球邻近关系和状态置信度补充边界/遮挡证据；不把插值当检测，不删除原始预测，不冒认持球为回合。对照基线选段和真实视频复核完整性，明确未人工标注的范围。
5. **最终回归**：安装后的包不依赖 `tools` 上游源码或原虚拟环境；真实比赛覆盖五佳、十佳、规则、API 故障降级、断点恢复、音画同步。核对依赖锁、模型获取/哈希、来源与许可证、复现命令和剩余问题后才完成目标。

## 已确认的事实与边界

- 独立核心位于本机 `tools/volleyball_analytics/src/ml_manager`，是 `masouduut94/volleyball-ml-models` 子模块；提交 `2374bfd859d6a03c78780d0aa1bae3d3a30dea83`，MIT，Copyright 2025 Masoud Masoumi Moghadam。`GameStatusClassifierModule.py` 有本机修正，须单独记录，不能把工作树冒充纯上游提交。
- `fast-volleyball-tracking-inference` 提交 `637c217b6589be50eba77687d3f5fa5ca103c175`，MIT，Copyright 2025 Alexander Sigatchov。
- `volleyball-highlights` 当前未找到根级许可证。保留其功能目标，号码裁切、OCR 证据与聚合自行实现，不复制未授权源码。
- 2026-09-10 通过沙箱外只读 `nvidia-smi` 确认四张 RTX 3090（每卡 24 GiB），驱动 `580.173.02`，采样时没有计算任务。沙箱内驱动不可见不等于机器没有 GPU；真实 GPU 验证须在可访问设备的执行环境进行。
- 三个现有虚拟环境均为 Python 3.12.3，但 NumPy、OpenCV、Pillow、SciPy 等不同；不能直接把上游宽松 `pyproject.toml` 当作已验证的统一环境。
- 旧 `tools/PINNED_UPSTREAM.md` 仍写 VolleyCut 和篮球项目，已与实际 VolleyMole 范围不符；整合时以本台账及新来源清单替代，不把无关篮球能力纳入。
