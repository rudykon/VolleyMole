# 成片目录与格式

`runs/` 是后台工作区，保存模型分析、缓存、临时视频、日志、渲染报告和验证证据。客户的成片目录为 `outputs/published/`。网页“我的成片”只读取这个目录，不扫描 `runs/`、旧输出目录或任务标题来推测成片。

## 目录职责

| 位置 | 内容 | 网页用途 |
| --- | --- | --- |
| `data/`、`data/uploads/sources/` | 原始比赛录像 | 比赛源片、创建剪辑输入 |
| `data/meme-assets/`、`data/materials/`、`data/uploads/materials/` | 配音、音效、短片素材 | 我的素材 |
| `runs/` | 中间产物、分析结果、缓存、日志、报告 | 后台处理和专业排错，不直接播放其中的视频 |
| `outputs/published/` | 已完整收录的成片包 | 我的成片、封面、播放、下载、剪辑详情 |
| `.local/web/` | 网页任务与源片封面缓存 | 服务内部状态，不属于成片包 |

单独放一个 MP4 到 `outputs/`，或者存在 `render_report.json` / `delivery.json`，都不会让它直接出现在“我的成片”。对原始录像做混音也不会自动成为成片。

## 一份成片一个目录

```text
outputs/published/
  <24位成片编号>/
    video.mp4       # 完整成片
    poster.jpg      # 从这份成片提取的真实封面
    manifest.json   # 作品信息和可供客户阅读的回合摘要
```

三者齐全且描述文件有效才会被列出。编号在首次收录时由输入成片的 SHA256 前 24 位生成，同一文件重复收录复用已有成片包。编号不承担内容校验职责，成片实际文件的完整 SHA256 单独写入描述文件。

视频统一为 **MP4 容器、H.264 视频、yuv420p 像素格式、AAC 音频**（没有音轨的视频允许音频字段为 null）。收录时使用无损重新封装，将 MP4 索引移到前部（faststart），便于浏览器加载和拖动；不重新编码画面。不符合编码规范的视频会明确报错，需要先转换。竖屏和横屏均可，尺寸和时长从实际文件读取。

封面为 JPEG，从成片的实际画面生成。收录过程在隐藏临时目录完成，视频整理、封面生成和清单写入全部成功后，才原子移入正式目录。失败时不展示半成品。

## manifest.json 第一版

| 字段 | 类型与含义 |
| --- | --- |
| `schema_version` | 整数 `1` |
| `id` | 与目录名一致的 24 位小写十六进制编号 |
| `title` | 作品名称，不使用后台任务类型充当标题 |
| `created_at` | 收录时间，Unix 秒数 |
| `match_date` | 比赛日期，无法确定时为 null |
| `collection` | 榜单类型，例如 `highlights` / `bloopers` |
| `design_suite` | 成片视觉套装，未记录时为 null |
| `video.file` | 固定为 `video.mp4` |
| `video.codec` / `pixel_format` / `audio_codec` | `h264` / `yuv420p` / `aac` 或 null |
| `video.duration` / `width` / `height` | 正数时长（秒）及实际展示尺寸（像素） |
| `video.bytes` / `sha256` | 最终成片字节数及完整 SHA256 |
| `poster.file` / `bytes` | 固定为 `poster.jpg` 及其字节数 |
| `highlights` | `[{"rank": 1, "title": "精彩扣球"}, ...]`；没有回合记录时为空数组 |
| `verification` | `passed` / `failed` / `unknown`，与命令退出成功分开记录 |

清单不复制原始报告，不保存源片路径、`runs` 路径、API 请求、密钥、模型参数或日志。网页详情接口只返回约定的客户字段，额外的私有字段不会透传。

`verification=passed` 要求收录时存在与输入成片完整哈希匹配的解码验证记录；它不表示语义识别质量经过人工确认。混音生成的新视频不会继承原片的检查通过状态。没有匹配检查记录时标记 `unknown`，仍可播放。播放器能读取文件，也不等于内容质量检查通过。

网页校验文件大小和 SHA256，文件被修改后不会继续使用旧清单。哈希按文件身份与修改时间缓存，正常浏览和分段读取无需重复扫描整个视频。完整复制三文件成片包到另一工作区同样有效，无需保留原来的绝对路径或文件时间戳。

## 怎样收录

网页的单视频、多局剪辑任务完成后，自动将本次渲染的最终视频收录到此目录，并把成片编号写入网页任务记录。仅执行分析、排名、回放复核、失败或取消的任务不收录。已有交付记录时只选择交付视频，交付视频缺失不会退回展示干净版或中间版本。

网页本地配音任务只有在输入本来就是已收录成片、混音报告确认视频未改变时，才收录新的配音版。输入是比赛源片或声音素材时，结果仍留在后台。

已有 CLI 任务可在专业任务报告里点击“收录成片”，或显式执行：

```bash
python -m volleymole.web.films --workspace /path/to/VolleyMole \
  --run runs/my-match --title "周末联赛 · 十佳球"
```

源码环境使用 `PYTHONPATH=src .venv/bin/python -m volleymole.web.films ...`。这只整理本地文件，不上传或发布到外部服务。收录不会删除后台原文件；清理后台时可以按需删除，成片包已经独立保存视频、封面和摘要。

收录失败会单独显示原因，底层命令的真实退出状态不变。修复格式或工具问题后可重新收录。网页的输出参数不能直接指向 `outputs/published/`，防止处理过程覆盖已经交付的成片。

## 清理与迁移

先确认成片包完整，再清理对应 `runs`。已收录成片的播放、下载、封面和详情完全不依赖 `runs`、模型缓存或旧任务记录。

旧视频不会因为存在历史报告就自动迁移，也不会自动恢复已删除的视频。先确认要保留的实际成片仍存在，再显式收录。归档或删除 `runs` 不会让任何片段进入成片列表。
