# 排球比赛五佳球／十佳球：核心功能需求

更新日期：2026-09-09

## 1. 产品范围

输入一场排球比赛的单个视频文件，输出五佳球或十佳球的竖屏短视频合集。产品只围绕三步主流程建设：**先准确分割回合，再为每个回合评估精彩度，最后把入选回合剪辑成片**。模型、球员号码识别、大模型和视频工具都服务于这三步，不单独构成产品目标。

第一版复用 `tools` 中已有的三个项目，不训练新模型；它们是实现手段：

| 项目 | 第一版职责 | 直接使用的输出 |
| --- | --- | --- |
| `volleyball_analytics` | 比赛状态、动作、球场和球的分析；提供回合边界证据 | `detections.jsonl`、`summary.json`、标注视频 |
| `fast-volleyball-tracking-inference` | 排球检测、轨迹提取、回合轨迹和竖屏跟球视频生成 | `ball.csv`、`track_*.json`、Reels |
| `volleyball-highlights` | 读取球衣号码，定位指定球员的出现时段 | 球员检测索引 JSON/CSV |

`volleyball-highlights` 只负责“该球员是否出现在回合内”的证据，不单独决定高光。高光排序由确定性规则预筛加大模型语义评审共同完成。

### 仓库边界

GitHub 仓库保存本方案、许可证和后续编排器源码。完整的 `tools` 检出、模型权重、比赛视频及 `data` 是本地依赖，不提交到 GitHub。运行前，操作者须在本机将三个上游项目放置在本文指定的 `tools/` 路径，并按各项目说明准备其模型和运行环境。

## 2. 第一版输入与输出

### 输入

- 一场比赛的 MP4、MOV 或 AVI 文件；初版支持单一连续视频和固定或轻微抖动机位。
- 用户选择 `top_k=5` 或 `top_k=10`。
- 可选的目标球员号码；未填写时生成整场比赛的通用十佳。
- 可选风格：默认竖屏 9:16、保留现场声音。

### 输出

每场比赛生成独立运行目录：

```text
runs/<match-id>/
├── analytics/             # 比赛分析原始结果
├── tracking/              # ball.csv、track_*.json
├── player/                # 球衣号码识别索引
├── previews/              # 每个候选回合的关键帧
├── match_manifest.json    # 统一的候选回合清单
├── edit_decision.json     # 排名、文案与剪辑点
├── clips/                 # 入选回合的竖屏片段
└── top5.mp4 或 top10.mp4
```

系统还须输出未入选回合和淘汰原因，便于复核。

## 3. 核心工作流

### 第一步：回合分割

从整场视频得到完整、可追溯的回合清单。系统结合比赛状态、排球轨迹和时间连续性确定每个回合的起止时间，并保存其原始检测证据。此步骤优先保证不漏掉有效回合；球员识别、动作识别和球场信息仅用来辅助判断边界。

### 第二步：精彩打分

对每个已分割回合计算精彩度，而非直接在整场视频中寻找高光。规则分数综合回合长度、有效球轨迹、动作、攻防持续程度、指定球员参与度和画面完整度；再由大模型依据候选数据和关键帧进行语义评审、排序和去重。结果输出五佳或十佳的剪辑决策。

### 第三步：剪辑成片

依据剪辑决策，从原视频提取入选回合，并使用球轨迹生成跟球竖屏构图；再添加简单排名和标题，保留现场声音，按排名合并为最终视频。轨迹缺失时可回退到原视频居中裁剪，不能因此阻断成片。

## 4. 统一回合数据

所有组件之间只通过原视频时间轴和以下格式交换结果。时间均为相对原视频的秒数。

```json
{
  "rally_id": "rally_0042",
  "start_sec": 842.3,
  "end_sec": 861.8,
  "duration_sec": 19.5,
  "tracking_json": "tracking/tracks/track_0042.json",
  "actions": ["receive", "set", "spike", "block"],
  "players": [{"number": 12, "presence_ratio": 0.72}],
  "ball_metrics": {
    "visible_ratio": 0.91,
    "trajectory_changes": 6
  },
  "rule_score": 71.5,
  "preview_frames": ["previews/rally_0042_start.jpg", "previews/rally_0042_peak.jpg", "previews/rally_0042_end.jpg"]
}
```

每个上游输出都必须记录来源项目、模型文件、参数和原始文件路径。未能关联有效轨迹或有效时间段的结果不得参与排序。

## 5. 第二步的打分规则与大模型职责

### 预筛规则

预筛应可解释、可配置，综合回合长度和有效球轨迹占比、扣球/拦网/接发/传球等动作事件、轨迹转折次数和攻防持续程度、目标球员出现比例，以及检测结果完整度。预筛不直接产出最终五佳或十佳，只负责过滤明显无效、重复或画面不完整的回合。

### 大模型

大模型 API 的输入为候选回合 JSON、每个回合最多三张关键帧，以及用户意图；不得上传整场视频来判断。它负责解释回合的可看性和可能的精彩事件、在候选中排序并保持动作和球员多样性、生成简短标题与字幕文案，以及指定安全的剪辑起止时间。

模型只能返回符合固定 schema 的 JSON，程序必须校验 `rally_id`、时间范围、数量与文件存在性后才执行渲染。模型未能返回有效 JSON 时，系统按规则得分降级排序并保留失败记录。

```json
{
  "title": "比赛十佳球",
  "selected": [{
    "rank": 1,
    "rally_id": "rally_0042",
    "clip_start_sec": 840.5,
    "clip_end_sec": 863.0,
    "title": "连续防守后的反击得分",
    "reason": "攻防回合长，包含救球、传球与终结扣球",
    "confidence": 0.86
  }]
}
```

## 6. 支撑三步流程的工具封装

第一版的“多智能体”是固定职责的工具封装，由单一编排器依次完成回合分割、精彩打分和剪辑成片；不实现可自由规划和任意互相调用的自治代理。

| 工具智能体 | 输入 | 输出 |
| --- | --- | --- |
| 分析智能体 | 原视频 | 比赛状态、动作、检测结果 |
| 回合智能体 | 原视频 | 球轨迹、轨迹段、候选回合 |
| 球员智能体 | 原视频、可选号码 | 球员出现时间索引 |
| 排名智能体 | 候选回合、关键帧、用户意图 | `edit_decision.json` |
| 渲染智能体 | 剪辑决策、轨迹 JSON、原视频 | 单回合 Reels、最终合集 |

编排器须保存每一步的状态和错误，支持从已成功的上一步继续运行；不同项目仍使用各自虚拟环境，通过命令行子进程调用，以避免依赖冲突。

## 7. 非目标

第一版不包含：比分识别、完整比赛技术统计、语音解说识别、自动配乐、复杂转场、人工图形剪辑时间线、实时直播分析、多机位融合、球员姓名识别和新模型训练。

## 8. 第一版验收

- 可对一段真实比赛视频生成五佳或十佳 MP4。
- 每个入选片段能在 `edit_decision.json` 和 `match_manifest.json` 中追溯到原视频时间段与证据。
- 指定球员时，优先选择其参与且号码识别置信度足够的回合。
- 成片可播放，包含正确数量的片段，保持音画同步，且为 9:16。
- 大模型 API 失败时仍能按规则生成可播放的降级版本。
