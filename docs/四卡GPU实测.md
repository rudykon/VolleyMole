# 四卡 GPU 实测（2026-09-10）

同一场 `data/样例视频/1.mp4`，四张 RTX 3090 确实共同参与了新鲜分析。
本次命令从输入检查到回合清单耗时 **615.642 秒（10 分 16 秒）**；
此前同源单卡为 **1048.111 秒（17 分 28 秒）**，观察到 **1.702 倍加速、
耗时减少 41.26%**。这是历史单卡与本次四卡的单次对照，不是独占、重复统计的基准。
运行中曾出现其他 GPU 进程，不保证其他机器或负载下达到相同比例。

## 四卡如何工作

- CUDA 0：状态识别；CUDA 1：动作检测；CUDA 2：人物检测。
- CUDA 3：VballNet 球轨迹，以及已有证据缺失时的辅助球检测。
- 四个模型工作线程并行，仍只有一次 PTS 解码。保留 90 帧大批次、
  30 帧状态窗口、9 帧球轨迹序列和 8 帧检测小批次，不截断轨迹历史。
- 各卡负载不同；解码、预处理、结果整理和落盘仍占时间，因此不是四倍加速。

运行进程 PID 1450302 在四张卡上均有显存分配；模型实际设备与指定设备相符。
ORT 首批记录 214 个 CUDA 内核事件及 22 个 CPU 内核事件，不宣称全部节点在 GPU 上。
中途进程快照记录本任务显存约 596 / 408 / 960 / 912 MiB；这不是峰值。
全设备采样峰值为 3799 / 3611 / 4212 / 4280 MiB，包含其他进程，不能全部归于本任务。

## 复现和记录

```bash
.venv/bin/volleymole run --video data/样例视频/1.mp4 --top-k 5 --ranker rules \
  --devices cuda:0,cuda:1,cuda:2,cuda:3 --stop-after manifest \
  --output runs/four-gpu/full-match --no-analysis-cache
```

省略 `--no-analysis-cache` 时，匹配当前代码、模型、设备顺序和素材的缓存可以复用。
代码更新会改变指纹，不能把复用时间当成新鲜四卡分析时间。
去掉 `--stop-after manifest` 可按现有流程继续成片。

原始记录位于本机 `runs/four-gpu/`（不提交 Git）：

- `comparison.json`：整场 13 项检查、哈希、计时、逐帧和边界比较。
- `full-match/timing_latest.json`、`full-match/inference_cache.json`：本次计时和执行证据。
- `gpu-snapshot-mid.json`：同一 PID 在四张卡上的进程快照。
- `short-92-comparison.json`、`installed-wheel-comparison.json`：短尾/OCR 和安装包一致性。
- `measured-source.tar.gz`：整场实测源码，SHA-256 为
  `176cfff9ab972f748a09c003b7a53e660e8b222566da6304ccbd8e8a8047a76e`。

原始检测对照为 `runs/integration/phase2-full-match`；回合清单对照为
`runs/integration/phase3-full-match`。两者分别用于隔离 GPU 调度变化和此前的回合算法变化。
