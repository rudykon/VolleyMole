# 按日期生成整场十佳球

`volleymole match` 用于一次比赛分成多个视频的情况。它默认选择整场十佳球；原有 `volleymole run` 仍处理单个视频，不会擅自扩大输入范围。

## 命名与分组

视频名称为 `年.月.日.局号.扩展名`，例如 `2026.1.6.1.mp4`、`2026.1.6.2.mp4`。同日期归为一场，局号按整数排序，因此第 10 局不会排在第 2 局之前。支持 MP4、MOV、MKV 等常用容器，扩展名不区分大小写。

- `2026.01.06` 与 `2026.1.6` 是同一日期。
- 同日期、同局号出现两个视频会报错，不随意挑选其中一个。
- 无效日期、零局号、不符合命名格式的视频会报错；非视频文件忽略。
- 扫描包括子目录；缺失局号会提示，仅使用实际存在的视频，不推测补齐。
- 默认假定同一天只有一场比赛；若同一天有多场，请放入不同输入目录，指定不同输出父目录分别运行。

## 常用命令

```bash
# 只检查分组，无 GPU、API 或输出写入
.venv/bin/volleymole match --input-dir data/样例视频 --list

# 只剪 2026.1.6 的整场十佳球，四卡推理
.venv/bin/volleymole match --input-dir data/样例视频 --date 2026.1.6 \
  --devices cuda:0,cuda:1,cuda:2,cuda:3 \
  --pipeline-depth 2 --auxiliary-device cuda:0 --vball-engine ort-bound \
  --render-workers 2 --design-suite matchday --quality 1080p

# 目录中所有日期，每场一条英文十佳球
.venv/bin/volleymole match --input-dir data/样例视频 \
  --device cuda:0 --design-suite aurora --design-language en
```

日期也接受 `2026-01-06`。`--top-k 5` 可改为整场五佳球。默认 `--ranker auto --analysis-mode auto --collection highlights` 已恢复完整回合预筛、语义排序与规则兜底；不启动全场事件理解。`--ranker rules` 完全不请求 API。

`--analysis-mode events` 显式启用事件理解；默认模式下，`--collection both|bloopers` 也会选择事件路线。显式 `--analysis-mode rallies` 仅支持精彩榜，不会把趣味榜静默替换成竞技回合。运行配置和整场汇总保存实际 `analysis_mode`；回合路线还记录 `ranking_mode` 和安全的 `fallback` 原因。

事件路线的 `--analysis-timeout 1800` 按每局独立计时，默认至少 40% 留给本地回合复核；粗读不能消耗这部分预算。慢速本地推理导致的清单等待也不占用复核保留时间。多局总耗时可能超过 1800 秒；阶段预算和耗时定义见[事件理解与双榜](事件理解与双榜.md#时限与验收)。

## 排名与画质保证

每局先完成独立分析和回合切分，不在这一阶段挑选各局五佳球或十佳球。默认回合路线对合并回合执行候选预筛与语义排名，API 失败时记录规则兜底；事件路线统一合并各局事件并分别打分选出两榜。没有“每局必须入选几球”的配额，精彩程度高的一局可能入选更多，也可能有某局没有入选。

完整回合路线恢复 `4399475` 的候选与规则评分：按配置排除过短、轨迹覆盖不足的回合，恢复时长、转折、动作数量评分及稀疏人数降权；规则排名保留轻度时间与动作多样性惩罚，时间惩罚只比较同一原片。事件路线仍保留短事件候选，两类清单按 `selection_mode` 隔离缓存，不能混用评分。

回合路线不足十个有效且互不重叠的回合会明确报错；事件双榜允许不足数量输出。事件分析超时、失败或覆盖不足时，汇总标记 `analysis_incomplete`，零事件不能当作正常的无精彩片段结论。竞技素材需要保留整个检测回合，只能在安全边界内调整前后上下文。规则评分不代表已经确认得分、扣杀成功或比赛胜负。

不先转码拼接整场原片：入选回合直接从对应原视频渲染，避免额外有损编码、跨局误切和不同分辨率/音轨的拼接问题。输出默认 1080×1920、30 fps，沿用项目现有预告、标题转场、回放和音画校验。素材细节仍受原片和现有装饰素材分辨率限制。

## 时间坐标与追溯

每局保留自己的本地秒数，不能把第 2 局的 `10 秒` 当成第 1 局的 `10 秒`。回合 ID 加局号前缀，例如 `set-0002__rally_0007`。预览、渲染、片头快切、慢动作回放和最终内容校验都先解析原片，再使用该局时间。

默认目录为 `runs/matches/日期-top10/`。以下为默认回合路线及规则模式的文件表；事件路线的事件时间线位于该目录，剪辑单、成片与校验文件分别位于 `collections/highlights/` 和 `collections/bloopers/`。

| 文件 | 内容 |
| --- | --- |
| `parts/set-0001/` 等 | 每局的独立分析、追踪和原始证据 |
| `match_manifest.json` | 整场所有回合、原片映射和局号；秒数均为对应原片的本地时间 |
| `edit_decision.json` | 统一排名的十个完整回合 |
| `selected_sources.json` | 每个名次对应的原片路径、局号、起止秒数 |
| `top10_lively.mp4` | 10 → 1 倒序播放的整场成片 |
| `verification_lively.json` | 完整解码、帧数及音视频时间检查 |
| `alignment_verification_lively.json` | 逐回合对照正确原片的画面与原声检查 |
| `title_card_readability.json` | 名次、标题和透明覆盖层检查 |
| `match_summary.json` | 整场处理结果与本次阶段计时 |

## 缓存与失败恢复

每局继续使用按原片身份校验的共享分析缓存。换模板、语言或画质不需要重新推理；重跑相同命令会验证已有阶段产物并复用。新增或修改一局会更新整场候选与排名，不会复用过时成片。`--output` 是场次父目录，建议使用独立目录保留不同视觉版本。

`--stop-after manifest` 停在整场回合清单，`--stop-after rank` 停在整场排名；`--rerun-from previews/rank/render/verify` 重做相应呈现阶段。`--no-analysis-cache` 强制重新推理各局。整场模式不接受单局 `--evidence-cache`、`--analytics-cache` 或 `--tracking-cache`，避免误把一局证据套到其他局。

批量处理按日期顺序执行；某场失败会明确终止并保留日志与此前完成的成片。修复原因后重跑原命令即可恢复。
