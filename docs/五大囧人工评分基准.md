# 五大囧人工评分基准 v1

本基准评价“画面中可解释的意外是否有趣、是否适合入选五大囧”，以独立真人判断作为参照。动作识别标签、笑声音量、官方集锦标签和模型解释都不能直接替代这个判断。

**当前交付是执行规范、匿名素材生成器、全空评分表、导入校验和评测程序；没有新增人工标签，也没有把模型输出改名为人工标签。** 用户无需亲自评分。本轮没有招募、联系评员或代替评员填写表格。等独立真人评分到位后才计算质量指标；空包运行的结果为 `null`，不是 0 分，更不是准确率。

## 1. 评价对象与分区

一个单位是同一真实事件的完整“铺垫 → 意外 → 后续反应”。不要求发生在有效回合中，发球准备、局间互动、热身均可进入采样池。保留原速、原始画面比例、必要上下文；不能用慢放、搞笑配音、文字解说或剪辑包装制造有趣程度。原视频已有广播文字无法消除，须在数据说明记录。

先锁定比赛身份，再按整场比赛分为 `train / dev / test`。同场录像的不同机位、不同节选、转播回放都属于同一个 `match_id`；同一赛事双方第二次交手可以另建比赛 ID。记录比赛日期、双方、视频出处、源文件哈希和时间基准。程序阻止相同源文件被放到不同比赛或分区，但无法仅靠哈希识别另一个转码版本，策划者仍须核对来源身份。

首轮建议 30 场以上，至少 10 场开发、20 场冻结测试；正式样本量应在开发集试评后根据效应大小和比赛间差异决定。这是采集目标，不是已经取得的数据。男女、业余/职业、固定机位/转播、音质与场馆应有分层记录；不从同一场截出很多事件冒充很多独立比赛。

测试池至少包含以下三个来源，单独保留数量和发现方式，评分包内隐藏它们：

| 采样来源 | 做法 | 能支持的结论 |
| --- | --- | --- |
| 多策略候选并集 | 合并旧规则、新模型、纯声音发现的候选，先按事件去重；保留所有被比较系统的前五结果 | 固定候选池的排序与前五质量 |
| 与模型无关的时间抽样 | 按固定随机种子，按比赛/比赛阶段抽取原素材区间，边界处扩上下文 | 减少只评价模型已发现片段的偏差；有限随机窗口仍不是全场召回真值 |
| 完整比赛独立人工巡检 | 由另组真人完整观看并记录事件，包括所有阶段；评分员随后盲评 | 才能建立全场候选召回率参照；本版程序没有自动生成这种标签 |

另建困难负例分层：普通失误、长而普通的回合、无关邻场笑声/欢呼、场外聊天、无法判断原因的倒地、疑似受伤或疼痛、镜头遮挡、反应缺失、意外后成功挽回、无笑声但明显有趣、静音比赛。分层名称只是采样原因，**不是给评员的答案，也不保证一定为负例**；只有实际真人判断才成为参照。VNL-STES 的动作标签不提供这些趣味标签，其静音素材不能用于笑声关联评测。

`import-timeline` 会导入全部事件并前后各加 3 秒上下文，不查看原分数，也不截取前 25 名。导入模型时间轴只能建立候选池，不能据此声称全场候选覆盖率。原区间仍是采样窗口，铺垫和反应边界留给真人填写。相同事件的不同算法边界先在私有映射中归为一个事件；无法自动确定重复时保留争议，不能靠本模型解释自动生成重复真值。

## 2. 独立盲评与声音对照

每个事件、每个条件至少安排 **3 位独立评员**；推荐一个 5–10 场的开发试评后再冻结规则。评员先用开发素材学习“直接看见什么”和“觉得是否有趣”的区别，测试阶段独立作答，不讨论。不展示模型名称、提示词、评分权重、原排名、候选策略和别人答案。

程序对每位评员独立随机排序，以匿名文件名分发原速视频，私有映射另存。评分包只发该评员的 JSON 表和所需匿名 `media/`，不发 `private_mapping.json`、原时间轴或模型结果。随机种子和清单在派发前冻结；不能根据模型结果换种子。评员使用不包含姓名/联系方式的稳定匿名身份，重复导入和同一人多次评价同一事件会被拒绝。

有音轨的原素材生成 `audio` 和 `silent` 两个版本；后者物理移除音轨。两版分给完全不同的评员组，至少 3 + 3 人，同一人不能先听声音再评价同一事件的静音版。两组人员需在开发试评时随机分配并尽量平衡排球经验，避免把组间经验差异误当声音效果。声音与静音的比较按相同比赛和事件匹配，不能把两组评分混成一份共识。

本来没有音轨的素材只生成 `silent` 表，单列为原生静音；不能当作去声音实验的配对样本。静音条件的笑声强度、笑声关联、无关笑声统一填 `null`。无音轨不等于“无人发笑”；安静且可清楚听见全段的音轨中没有笑声，才可填笑声 0。

盲化不能遮蔽观众对球员、比赛或广播的既有记忆。评员若看过相同片段，应在事实说明注明，策划者将该次评价列为暴露样本，重新安排未见过素材的独立评员。v1 自动校验重复身份，但不能验证真人身份或识别这种既有记忆。

## 3. 作答顺序与量表

先看完整视频，再写直接观察和过程边界；**独立填写总体有趣度及入选适合度，然后填写分析维度**。总体分不能由四个维度加权算出，不能参照当前模型的 35%/25%/25%/15% 公式，否则评测会变成模型和自己的公式互相验证。

所有分数为整数 `0–4`；`null` 表示无法判断、不适用或证据缺失，需要写原因。`completed=false` 是尚未作答；`completed=true` 配合 `null` 才是评员已经看过后判断未知。不得因为缺证据把某项直接打 0。

| 字段 | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| `overall_fun` 总体有趣度 | 看完整过程仍无可解释趣味 | 有轻微趣味，但不足以吸引再次观看 | 趣味明确，力度一般 | 明显好笑或令人忍俊不禁，值得分享 | 过程异常鲜明，有强烈且可复述的趣味 |
| `selection_suitability` 五大囧入选适合度 | 不宜入选，含普通无趣失误、伤痛取乐等 | 不推荐，趣味或完整性不足 | 可作备选，但不是自然的前五选择 | 推荐入选，事件完整且趣味充分 | 强烈推荐优先入选，无需字幕编造理由 |
| `unexpected_contrast` 意外与反差 | 合乎预期，无反差 | 小偏差，通常会出现 | 明确的动作/结果反差 | 明显出人意料，前因后果可辨 | 多步反转或非常罕见的反差，证据完整 |
| `related_laughter` 相关笑声 | 音轨足够清楚，完整观察到无相关笑声 | 可确认与本事件相关的轻微短笑 | 清晰的一人或少数人发笑 | 多人明显发笑并与事件同步 | 持续集体发笑且音画归属清楚 |
| `narrative` 事件叙事完整性 | 看得到动作，但无法建立前后关系 | 只见突发瞬间 | 能解释意外，但缺少必要铺垫或后果 | 铺垫、意外、后果/反应完整 | 完整且紧凑，关键反差无需额外猜测 |
| `player_reaction` 球员与同伴反应 | 人物可见且观察充分，没有明显反应 | 轻微个人表情/动作 | 清晰的单人或两人反应 | 多人明显互动，如捂脸、相视、击掌 | 多人持续且有来回的互动，强化事件趣味 |

量表的 4 不由音量、人物数量或时长直接触发；它们只是可观察证据。没有笑声的高反差事件仍可给很高总体分；完整的普通失误可以叙事 3、总体 0。失误、扑倒、夸张表情本身不证明趣味。笑声若来自邻场，相关笑声不能给正分；归属不清填未知。

`selection_suitability` 独立考虑公开展示该事件是否合适。疑似受伤、疼痛、争执羞辱等不能因为“看起来好笑”而自动入选；记录 `injury_suspected` 和 `safe_to_include`，不要为了方便取舍更改 `overall_fun`。事实与价值判断分别保留，争议交给后续仲裁。

状态字段均为 `true / false / null`：

- `event_visible`：画面足以直接看出本次事件。
- `boundary_complete`：窗口保留解释本事件所需的开头和结尾。
- `injury_suspected`：看到可能伤痛的迹象；不要求评员作医学判断。
- `safe_to_include`：适合作为趣味集锦公开展示。
- `laughter_linked`：笑声可以归属于此事件。
- `ordinary_error`：仅为普通处理失误，没有明确特殊反差。
- `unrelated_laughter`：有清楚的笑声，但不是针对画面中该事件。

`stages.setup / unexpected / reaction` 各记录 `start_sec / end_sec`，时间从匿名片段起点 **0 秒** 开始。每一对一起填数字或一起填 `null`，不能超出片段；三个阶段起点按发生顺序排列，反应可与意外过程交叠。不清楚的边界不猜。源时间可由策划者通过私有映射加上 `clip_start_sec` 恢复。

`observed_facts` 用一两句话记录可核查事实，例如动作发生后球是否仍在比赛中、同伴如何反应；这里不提供任何真实测试片段的预填答案。缺失视角、看不清的球路和语音内容写进 `unknown_reason`。评分导入必须声明 `human_only=true` 和匿名 `annotator_id`；程序只校验声明，不能把声明本身作为身份真实性证据。

## 4. 争议与仲裁

保留每位评员的原始结果，不以“多数人同意”为由覆盖少数意见。以下进入争议队列：同一维度相差至少 2 分；布尔事实出现相反意见；疑似伤痛或安全性不一致；无法确定前后边界；明确指出看过片段。程序自动标记前两项，其余由策划者依据备注进入队列。

由不参与模型开发、未见模型分数的第四位评员看更长上下文，写一份独立仲裁记录：`item_id`、条件、争议字段、追加证据区间、结论/未知、理由、仲裁者匿名 ID、原始表哈希。伤痛无法排除时保留未知，不强求一致。原始一致性指标仍在仲裁前计算。

v1 评测主结果只用独立原始评分的中位数/多数判断，**没有自动读入仲裁结论覆盖原评分的功能**。仲裁结果可另作描述性分析或后续单独版本；不可据仲裁结果回头调测试集提示词再报告同一个冻结测试分数。开发集可用于调整定义和权重，测试集只用于冻结后的一次比较；重大修改需新测试比赛或明确披露重测。

## 5. 指标与适用范围

一致性采用适用于多评员、序数尺度及缺失值的 Krippendorff α；这是方法选择依据，而非对“五大囧天然客观”的保证。[Hayes 与 Krippendorff 原论文](https://www.tandfonline.com/doi/abs/10.1080/19312450709336664)讨论了这些适用性质。

程序分别报告六个维度、两个条件的序数 α，用参与可配对项目的经验类别频数定义序数距离，项目按 `1/(m−1)` 构造 coincidence matrix。只有 1 个已知评分的项目不进入 α；若全部评分只有同一类别，期望分歧为零，α 报未定义，不能写成完美可靠。同步报告可配对项目数、评分数以及具有至少 3 个已知分数的项目数。v1 不输出 α 的置信区间，不把单一阈值作为数据质量自动通行证。

每个事件需至少 **3 个已知总体分**才有中位数参照；3 份已提交但其中 1 份未知，不足以建立该项参照。布尔事实也需至少 3 个已知判断且无平票才产生多数值。分歧始终独立列出。

每场、每个系统分别报告：

| 指标 | 定义与未知处理 |
| --- | --- |
| `top5_fun` | 系统实际返回的前至多 5 个事件的人工总体有趣度中位数均值；任何入选项缺少参照则本场未知 |
| `top5_suitability` | 同上，使用独立人工入选适合度 |
| `suitable_fraction_returned` | 返回项中适合度中位数 ≥ 3 的比例；分母为实际输出数量 |
| `unsafe_fraction_returned` | 返回项中多数评员判断不宜公开展示的比例；任何入选项安全性未知则该比例未知 |
| `ndcg5_judged_pool` | 用全评审池的适合度中位数作为理想榜单，线性增益 `g / log2(rank+1)`；整池任一参照缺失则不算；理想增益全为零则未知 |
| 数量与缺失 | 实际入选数、缺少的五个名额、已判断入选数、候选池大小、未能算指标的比赛数 |

nDCG 根据分级相关性和排名折扣评价前列结果，方法来源是 [Järvelin 与 Kekäläinen 原论文](https://faculty.cc.gatech.edu/~zha/CS8803WST/dcg.pdf)。v1 明确采用线性增益及 `log2(rank+1)` 折扣，是固定工程口径，不声称逐字复刻原论文全部变体。若系统自愿少输出，缺少名额在 DCG 中没有增益；这不等于把未知人工分设为 0。少于五个事件时不会强制补普通失误，报告实际数量即可。

模型结果只能引用评审池中的唯一 `event_id`；未加入池的事件、重复事件和漏交的比赛结果都会报错。模型失败或无输出要显式填空数组；有完整正参照时其 nDCG 为 0，质量均分未知。不得悄悄移除失败比赛来提高均分。

若某场没有候选，声明过的比赛仍保留在报告中，模型也须显式提交空榜。这种比赛没有评审池参照，质量和 nDCG 均为未知，状态为 `empty_candidate_pool`；`match_coverage` 列出声明比赛数、有候选比赛数及零候选比赛 ID。它与“有完整人工正参照但模型返回空榜”的情况不同，不能把缺少参照解释为模型零分或满分。

汇总对每场指标等权取均值，再按整场比赛有放回抽样 2,000 次计算描述性 percentile 95% 区间。这样不把同场相关片段当独立样本；聚类重采样依据见 [Field 与 Welsh 原论文](https://academic.oup.com/jrsssb/article-abstract/69/3/369/7109361)。少于 10 个具有已知指标的比赛不输出区间；10 是本版保守报告约定，不是统计可靠性的保证。已知比赛之外的缺失数量同时报告；未建模评员抽样的不确定性，不能用该区间代替新评员/新人群泛化评测。

各系统的汇总均值只包含该系统具有已知指标的比赛，**覆盖比赛不同的两个均值不能直接横比**。先查看每场结果、`matches / missing_matches` 和实际输出数量；只在相同已评比赛、相同条件及参照完整性下讨论优劣。v1 不自动生成系统之间的共同覆盖集合比较，也不把未知比赛补为 0。

v1 不计算全场候选召回、解释事实正确率、跨系统显著性检验、真人成对偏好胜率或仲裁后指标。前两项需要不同的事实参照；成对偏好如以后实施，应对固定同一比赛的两套前五顺序随机左右、隐藏系统身份、独立填写“左更好/右更好/相近/无法判断”，不能把上述模型分差改成真人偏好票。本版总体适合度已经是独立直接判断，后续偏好研究可另行预注册。

## 6. 可执行流程

工具为 [scripts/blooper_benchmark.py](../scripts/blooper_benchmark.py)，评分与指标实现为 [src/volleymole/blooper_benchmark.py](../src/volleymole/blooper_benchmark.py)。无需新的 Python 包，裁剪需要现有 FFmpeg。

从现有单素材时间轴生成候选池：

```bash
.venv/bin/python scripts/blooper_benchmark.py import-timeline \
  --timeline runs/某场/event_timeline.json --video /绝对路径/比赛.mp4 \
  --match-id match-001 --split dev --output /tmp/blooper-pool.json
```

或提供自己已有的原素材区间清单；如下只是输入格式，不是标注数据。多个比赛合并在 `matches` 数组中：

```json
{
  "matches": [{
    "match_id": "match-001",
    "split": "dev",
    "pool_scope": "candidate_pool_only",
    "sources": [{
      "source_id": "single",
      "path": "/绝对路径/比赛.mp4",
      "duration_sec": 3600,
      "audio_available": true
    }],
    "events": [{
      "event_id": "source-window-001",
      "source_id": "single",
      "clip_start_sec": 100,
      "clip_end_sec": 125,
      "sampling_origin": "fixed_seed_time_window"
    }]
  }]
}
```

生成空包，然后物理裁剪匿名素材：

```bash
.venv/bin/python scripts/blooper_benchmark.py prepare \
  --input /tmp/blooper-pool.json --output runs/blooper-human-v1 \
  --raters-per-condition 3 --seed 20260912
.venv/bin/python scripts/blooper_benchmark.py render --package runs/blooper-human-v1
```

输出目录包含私有映射、每位评员的独立随机顺序 JSON 空表、每位评员独立的 `review_audio_01.html` / `review_silent_01.html` 离线页面、匿名音视频和媒体哈希。已有目录或媒体不会被覆盖。只把某位评员的页面、表和对应素材交给该评员；`prepare` 不会联系任何人，也不会自动上传材料。边界、总体分、所有分析分和状态最初全部为 `null`，`completed=false`。

评员可直接在浏览器打开自己的 HTML 页面，观看播放器、填写总体分和分析分、选择状态、以片段时间记录三个阶段，然后下载 JSON。时间输入旁可填入播放器当前时刻；静音页禁用笑声相关评分。本人声明和“本段已完成”均须主动勾选，不会自动代勾。下载文件与原表使用相同 schema，可直接交给 `evaluate`；仍可选择手工编辑原 JSON。页面仅保留当前内存，离开前下载，页面没有网络依赖也不上传答案。

HTML 必须留在分发包根目录，匿名视频位于同级 `media/` 子目录。不要把私有映射或其他评员页面一并分发。已有空包可追加生成页面：

```bash
.venv/bin/python scripts/blooper_benchmark.py pages --package runs/blooper-human-v1
```

该命令只读取尚未填写的 `assignments/*.json`，拒绝把已有答案或本人声明预填入页面，也不覆盖已经生成的页面。

真人看完以后在页面或自己的表填写匿名身份、声明 `human_only=true`，逐项填写分数/事实/未知理由并将该项改为 `completed=true`。不要把模型输出复制入表。表内顺序与媒体路径保持不动。汇总时传入每位评员唯一的一份最终下载文件（`*.ratings.json`）或完成后的原 JSON，避免同时导入空表、旧版草稿和最终版。

模型排名单独保存在另一个文件，不交给评员。每场都要写，包括没有返回事件的场次：

```json
{"systems": [{"system_id": "frozen-model-a", "matches": [
  {"match_id": "match-001", "ranked_event_ids": ["source-window-001"]}
]}]}
```

将每位评员唯一一份最终下载文件放入 `runs/blooper-human-v1/collected/`，不要放入原空表或旧草稿。目录可先创建：

```bash
mkdir -p runs/blooper-human-v1/collected
```

导入收集到的实际评分并计算报告：

```bash
.venv/bin/python scripts/blooper_benchmark.py evaluate \
  --package runs/blooper-human-v1 \
  --ratings runs/blooper-human-v1/collected/*.ratings.json \
  --predictions /tmp/frozen-predictions.json --split dev \
  --output runs/blooper-human-v1/report.json
```

若仍未收集到人工评分，可另行运行空表管道检查：

```bash
.venv/bin/python scripts/blooper_benchmark.py evaluate \
  --package runs/blooper-human-v1 \
  --ratings runs/blooper-human-v1/assignments/*.json \
  --predictions /tmp/frozen-predictions.json --split dev \
  --output runs/blooper-human-v1/empty_report.json
```

空表检查中 `human_completed_rows=0`，α、前五质量和 nDCG 全部是未知。这个结果只证明评测工具可运行，不能用于宣称趣味识别已达到某种准确性。
