# 事件理解与双榜

`run` 和 `match` 的 `--ranker auto` 现在走全场事件链路。已有规则排序和三帧评审函数保留为历史兼容接口；新自动入口不调用规则前 25 名预筛、三帧评审或末端“大排名”。`--ranker rules` 是显式旧规则模式，只支持竞技集锦。

```bash
volleymole run --video match.mp4 --collection both --top-k 10 \
  --vision-model YOUR_AV_MODEL --semantic-concurrency 6 \
  --analysis-timeout 1800 --output runs/match-events

volleymole match --input-dir data/matches --collection both --top-k 10
```

接口和密钥仍读取现有 `llm_api.json` 的 `llm` 节点及原有环境变量；不要把密钥放入提示词或命令行。`--vision-model` 优先于 `--model`，同一个理解模型输出事实和九个维度，程序分别组合两榜，不再调用文本模型生成总排名。

## 分析和采样

- 默认 24 秒分块、4 秒重叠、粗读 2 FPS，完整覆盖准备、局间和比赛；复核默认 8 FPS、最大上下文 90 秒。每个请求记录实际源 PTS 采样时间，不能把“设置了 8 FPS”当成已经看清每次触球。
- 新鲜共享推理将已有解码帧写入 `event_frames/`，视频理解按块消费。推理缓存命中或独立推理时按需要读取原片准备证据。密集帧保存在本地，粗读只发送低帧率子集。音频单独解码一次并缓存；它与视频使用相同源时间基准。
- 默认 `--semantic-modality frames-audio` 发送有明确源时间的连续图像序列和同步 `input_audio` WAV。这是显式视频帧序列协议，不依赖供应商对上传视频的隐式 1 FPS 抽样。服务须同时接受 `image_url`、`input_audio` 和 JSON 输出；HTTP 成功只能验证格式兼容，不能证明模型识别快速排球动作的能力。
- 仅支持图片的服务可以显式选择 `--semantic-modality frames`。没有声音模型时，笑声维度为未知；本地音量/瞬态测量不等于声音类别。
- 粗读与本地推理并行，复核使用已有姿态、动作及相机补偿后的人物相对运动。快速球运动须有足够采样和人物尺度；腕部接近加音频瞬态仅标为触球假设。过网、落点、真实触球次数仍需可靠观察，默认未知。
- 复核覆盖粗读事件和未被覆盖的本地回合假设，不受旧规则名次限制。每个合并候选最多追加一轮；成功的空复核撤销候选，失败或超时保留粗读事实并标记 `unreviewed`。过长上下文单独记录未复核原因。

## 本地声音事件模型

可用 `.venv/bin/python scripts/install_sound_model.py` 安装 PANNs 官方 **framewise** 声音事件权重，安装到模型目录后自动启用；本地本次已完成安装和公开音频评测。也支持 `--sound-model export.ts --sound-labels labels.json` 指定其他兼容导出，`--no-sound-model` 关闭，`--sound-device cuda:0` 选择声音推理设备。导出协议：输入为 32 kHz 单声道浮点波形 `[1, samples]`；输出字典的 `framewise_output` 为 `[1, time, classes]` 的 0–1 概率。`labels.json` 是与训练输出完全对应的类别字符串数组。PANNs 的 10 ms 输出来自 320 ms CNN 决策插值，不能当作精确触球时刻；部署和来源见[声音模型部署](声音模型部署.md)。

普通 PANNs 原始 checkpoint 或 clipwise 分类器不能直接当作此导出文件。模型不符合协议时会记录失败，不会自动改用音量峰值冒充笑声。类别概率仅为本地假设，现场笑声是否来自画面中的事件仍需音画关联。

## 分数与剪辑

`defaults.json` 的 `event_weights` 配置两套初始权重；`event_score_threshold` 默认 55。各维度统一 0–4 量表，量表和例子见 `prompts/understand_events.md`。缺失项为 `null`，输出已观察权重和未知维度；仅对已观察维度归一化，已观察权重不足 60% 不入选。这是首版策略，需在训练/校准比赛上按人工偏好调整，不能用测试集调权重。

竞技榜要求完整回合，扩展剪辑以保留相关的完整检测回合；不因长度、转折数量或人数三次方直接加减分。趣味榜要求明确反差、可理解的事件过程和排除疑似受伤；没有笑声仍能入选。独立评分后再去重和排除剪辑重叠，保留精彩度顺序，没有时间接近扣分。暂不施加额外多样性偏好。

趣味剪辑使用 `event_v1` 协议，严格保留 `required_start_sec` 至 `required_end_sec` 的铺垫、意外和反应；原有完整回合时间校验不放宽。两类剪辑都继续检查源视频范围与重叠、完整解码、30 FPS 帧数、音视频起点／时长，并独立将成片抽样画面和原声与对应原片区间比对。回放使用事件关键时刻及其证据引用。

输出目录：

```text
run/
  event_timeline.json          # 共用事件、双维度、请求采样和未完成记录
  audio_events.json           # 本场背景归一化与声音事件假设
  collections_report.json
  collections/highlights/     # 独立清单、片段与成片
    verification[_lively].json            # 解码、帧数、音视频时间
    alignment_verification[_lively].json  # 原画面／原声内容对齐
  collections/bloopers/       # 同样生成两类校验报告
```

五佳球/十佳球由 `--top-k` 决定；趣味榜最多五段。素材不足输出实际数量和原因；零段只写报告，不生成空视频。小于五段时片头快切也使用实际数量。两榜、切换 top-k 和重复运行共用源身份、模型、提示词和采样配置匹配的事件缓存，`--no-analysis-cache` 强制新分析。

## 时限与验收

`--analysis-timeout` 是从本地推理启动前开始的**事件发现/复核预算**，跨局模式共用绝对截止时间；单请求使用剩余预算和 `--api-timeout` 的较小值，并限制重试次数（默认 1）。截止后停止排新请求，用已有证据生成报告。它不是整个命令的强制终止时间：本地推理、模型加载、已启动的系统操作、渲染与输出校验仍需安全结束。完整命令耗时记录于 `timing_latest.json`，跨局模式记录于 `match_summary.json`；请求记录包含上传到响应返回的耗时，渲染阶段也有独立记录。

按比赛划分 train/calibration/test，标注精彩和趣味事件源区间、期望剪辑边界，并由人工裁判标注入选质量和解释是否正确。运行：

```bash
python scripts/evaluate_events.py annotations_and_runs.json --output evaluation.json
```

输入字段见脚本模块说明。报告按比赛/榜单输出候选覆盖率、前五人工质量、解释正确率、剪辑完整性，以及同硬件、同输出规格、同缓存条件的端到端中位数/P95。未评审、未匹配和样本数量均显式保留。性能基线必须包含上传、排队、渲染与校验，不得只比较 API 时间。

已加入合成测试：静音和音量归一化、相机平移、短精彩/长普通回合、无关笑声引用、未知证据、疑似受伤、跨源去重、剪辑边界、一次复核与共享缓存。Actions 的公开回归还会构造 4 秒的测试画面和正弦原声，从趣味榜编排入口执行完整媒体校验，并要求产生 `alignment_verification.json`；这条回归只防止内容对齐检查再次从新入口脱落。真实比赛标注、真实音视频服务能力、PANNs 导出权重和硬件性能仍需现场验证；“较旧版增加不超过 25%”是优化目标，尚非实测承诺。

每场标注也可用 `"run_directory": "runs/match-events"` 替代 `predictions`，脚本会读取实际事件时间轴及两榜剪辑单，避免手工复制预测结果。

本次开发验证记录（2026-09-11）：已配置的 GLM-5.2 接口接受了生成的 8 秒测试图案与正弦音频，粗读包含 16 个有 PTS 的视频帧，返回合法空事件列表；该测试验证请求协议兼容，未验证听觉内容识别或真实排球理解。另用合成事件完成了单段趣味集锦的 1080p 渲染、完整解码、时间及标题校验。这些合成检查不能代替真实比赛评测。

2026-09-12 真实比赛复测：同一服务对 GLM-5.2 图像请求返回 HTTP 400，错误为该模型不支持多模态。上面的历史合成响应不能作为当前能力保证。公开动作评测另选该服务列出的视觉模型，实际模型、采样时刻、失败数与原标签隔离情况记录在评测产物中；原比赛数据范围见[公开排球数据源](公开排球数据源.md)。
