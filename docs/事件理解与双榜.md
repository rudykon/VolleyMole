# 事件理解与双榜

`run` 和 `match` 默认精彩榜已恢复完整回合预筛、三帧语义排序与规则兜底。本文描述可选的全场事件路线：通过 `--analysis-mode events` 显式启用，或在默认 `--analysis-mode auto` 下选择 `--collection both|bloopers`。仅 `--ranker auto` 不再自动启用事件理解。

事件路线不调用规则前 25 名预筛、三帧评审或末端“大排名”；其严格证据要求和不足数量输出保持不变。`--analysis-mode rallies` 只支持精彩榜；`--ranker rules` 成片只支持回合路线，完全不请求 API（事件路线的本地 `--stop-after manifest` 阶段也可使用规则模式）。回合路线恢复以历史提交 `4399475`（事件双榜引入前）为行为基准，包含历史候选排除与评分，并保留当前多局合并、同源重叠排除与源画面／原声校验，并非回滚整仓或恢复旧 AI 策展脚本的固定选段。

```bash
volleymole run --video match.mp4 --collection both --top-k 10 \
  --vision-model YOUR_AV_MODEL --semantic-concurrency 6 \
  --analysis-timeout 1800 --review-budget-fraction 0.4 --output runs/match-events

volleymole match --input-dir data/matches --collection both --top-k 10
```

接口和密钥仍读取现有 `llm_api.json` 的 `llm` 节点及原有环境变量；不要把密钥放入提示词或命令行。`--vision-model` 优先于 `--model`，同一个理解模型输出事实和九个维度，程序分别组合两榜，不再调用文本模型生成总排名。

## 结构化输出接口

事件理解使用 `response_format.type=json_schema`、`strict=true`，不再仅使用 `json_object`。后者只约束 JSON 格式，不保证字段或证据关系符合项目协议；参数及降级行为见 [AiHubMix 结构化输出文档](https://docs.aihubmix.com/cn/api/Structured-Output)。生产流程与模型探测共用 `event_schema.py`，所有对象禁止额外字段。严格 Schema 也不能代替本地的时间、证据和音画关联检查。

网络协议现为 `frame_anchors_v3`；落盘事件和后续评分、剪辑仍使用 canonical v1，不能把两个协议混用：

| 内容 | 模型返回的 wire v3 | 本地 canonical v1 |
| --- | --- | --- |
| 动作、剪辑起止及峰值 | 5 个 `*_frame` 字段，引用输入画面 ID | 5 个 `*_sec` 字段，由原始帧 PTS 确定 |
| 直接观察、后续、反应 | 统一 `facts` 数组，包含 `kind/text/frame_id/support_id` | 按类别分为 `observations/aftermath/reactions`，每条含 `text/time_sec/evidence_ids` |
| 九维评分 | 九项数组，每项 `{dimension, value, fact_indexes}`，明确名称唯一完整，索引从 0 开始且只属于本事件 | 以维度名为键的 `{value, evidence_ids}`，只展开所引用事实的已有证据 |

每次响应最多 3 个事件，每事件最多 12 条事实。每条事实是明确帧锚上的原子观察，不能用一帧证明“先接球再扣球”的整个过程；多个观察可以共同支持事件解释。`support_id` 仅可为同时段的声音、音频或本地运动证据，也可为 `null`。本地由 `frame_id` 获取精确源 PTS；即使辅助音频覆盖整块上下文，也不会用音频中点替代事实时刻。辅助证据继续执行原有 ±1 秒时间容差检查。

5 个显式帧锚必须先满足剪辑包住动作、动作起点早于终点、峰值位于动作内的顺序。之后只将剪辑区间扩展为显式剪辑锚与本事件 `facts` 中全部事实帧的包络；即使某条事实没有参与九维评分，也保留其已观察的铺垫或后续。不排序修复错误锚、不改变动作起止或峰值、不将 `boundary_complete=false` 改成 `true`。缓存保留原始 `wire_response`、`wire_protocol`、canonical 事件及 `time_derivation`，可对照审计每一项推导。

`decode_event_response()` 编译后仍执行原有 `validate_events()`。未知分数必须是 `null` 且不带事实索引，非未知分数必须引用真实存在的事实；不填造事实、不补分、不降低入榜门槛。正向笑声评分仍要求声音与画面证据及明确关联，运动强度仍要求可靠相机补偿测量。顶层数组、额外字段、虚构证据、越界评分索引和旧 canonical 格式不能冒充有效 wire 响应。5 个锚及所有事实 `frame_id` 都必须属于本次输入且 PTS 在上下文内，否则直接拒绝，不吸附到邻近帧或裁到上下文边界。请求记录保存 Schema 指纹、推理参数和结构化输出降级的安全分类；网关降级既不自动判失败，也不意味着 Schema 强制生效。

评分数组按明确的 `dimension` 名称映射，不按位置猜测；无名、重名、缺项、未知名称及额外字段均拒绝。旧 v2 的完整九键命名对象可无损兼容；原响应和 `dimension_encodings` 保留实际编码形式。这不改变分数、事实索引或业务证据约束。

传输层只接受一个完整 JSON 值，或恰好包住该值的一个完整 JSON 代码围栏；不截取正文、不补括号、不修复尾逗号，并拒绝重复键、非有限数字和不完整响应。事件契约错误、非法 JSON、连接中断及 HTTP 408/429/5xx 共用 `--semantic-retries` 的有限尝试额度（默认 1 次重试），不为不同错误分别新增预算；HTTP 400/401 不重试。协议纠错仍用同批原始证据、严格 Schema 和本地业务校验，不把失败机械转成空数组。成功与最终失败均保留实际 `attempts` 和安全分类的 `retry_history`；耗尽重试或截止时间后仍按失败统计，无效结果不写成功缓存。

当前指定模型为 `glm-5.3-flash`。推理强度可通过 `--semantic-reasoning-effort low` 显式传入，不指定时不发送该参数。它与输出格式是独立设置；参数用法见 [AiHubMix 统一推理参数](https://docs.aihubmix.com/cn/api/unified-inference)。示例（仅在已授权上传画面后使用）：

```bash
volleymole run --video match.mp4 --collection both --top-k 10 \
  --vision-model glm-5.3-flash --semantic-modality frames \
  --semantic-reasoning-effort low --semantic-frame-width 224 \
  --analysis-timeout 1800 --review-budget-fraction 0.4 --output runs/match-events
```

该参数进入缓存指纹及运行配置；Schema 代码变化也使旧事件响应缓存失效。上述小图设置用于接口验证，不能作为动作识别准确率保证。

## 分析和采样

- 默认 24 秒分块、4 秒重叠、粗读 2 FPS，完整覆盖准备、局间和比赛；复核默认 8 FPS、最大上下文 90 秒。每个请求记录实际源 PTS 采样时间，不能把“设置了 8 FPS”当成已经看清每次触球。
- 新鲜共享推理将已有解码帧写入 `event_frames/`，视频理解按块消费。推理缓存命中或独立推理时按需要读取原片准备证据。密集帧保存在本地，粗读只发送低帧率子集。音频单独解码一次并缓存；它与视频使用相同源时间基准。
- 默认 `--semantic-modality frames-audio` 发送有明确源时间的连续图像序列和同步 `input_audio` WAV。这是显式视频帧序列协议，不依赖供应商对上传视频的隐式 1 FPS 抽样。服务须同时接受 `image_url`、`input_audio` 和 JSON 输出；HTTP 成功只能验证格式兼容，不能证明模型识别快速排球动作的能力。
- 仅支持图片的服务可以显式选择 `--semantic-modality frames`。没有声音模型时，笑声维度为未知；本地音量/瞬态测量不等于声音类别。
- 粗读与本地推理并行，复核使用已有姿态、动作及相机补偿后的人物相对运动。快速球运动须有足够采样和人物尺度；腕部接近加音频瞬态仅标为触球假设。过网、落点、真实触球次数仍需可靠观察，默认未知。
- 复核覆盖粗读事件和未被覆盖的本地回合假设，不受旧规则名次限制。每个合并候选最多追加一轮；成功的空复核撤销候选，失败或超时保留粗读事实并标记 `unreviewed`。过长上下文单独记录未复核原因。

## 本地声音事件模型

可用 `.venv/bin/python scripts/install_sound_model.py` 安装 PANNs 官方 **framewise** 声音事件权重，安装到模型目录后自动启用；本地本次已完成安装和公开音频评测。也支持 `--sound-model export.ts --sound-labels labels.json` 指定其他兼容导出，`--no-sound-model` 关闭，`--sound-device cuda:0` 选择声音推理设备。导出协议：输入为 32 kHz 单声道浮点波形 `[1, samples]`；输出字典的 `framewise_output` 为 `[1, time, classes]` 的 0–1 概率。`labels.json` 是与训练输出完全对应的类别字符串数组。PANNs 的 10 ms 输出来自 320 ms CNN 决策插值，不能当作精确触球时刻；部署和来源见[声音模型部署](声音模型部署.md)。

普通 PANNs 原始 checkpoint 或 clipwise 分类器不能直接当作此导出文件。模型不符合协议时会记录失败，不会自动改用音量峰值冒充笑声。类别概率仅为本地假设，现场笑声是否来自画面中的事件仍需音画关联。

## 分数与剪辑

`defaults.json` 的 `event_weights` 配置两套初始权重；`event_score_threshold` 默认 55。各维度统一 0–4 量表，量表和例子见 `prompts/understand_events.md`。缺失项为 `null`，输出已观察权重和未知维度；仅对已观察维度归一化，已观察权重不足 60% 不入选。这是首版策略，需在训练/校准比赛上按人工偏好调整，不能用测试集调权重。

竞技榜要求完整回合，扩展剪辑以保留相关的完整检测回合；不因长度、转折数量或人数三次方直接加减分。趣味榜要求明确反差、可理解的事件过程和排除疑似受伤；没有笑声仍能入选。独立评分后再去重和排除剪辑重叠，保留精彩度顺序，没有时间接近扣分。暂不施加额外多样性偏好。

趣味剪辑使用 `event_v1` 协议，严格保留 `required_start_sec` 至 `required_end_sec` 的铺垫、意外和反应；原有完整回合时间校验不放宽。两类剪辑都继续检查源视频范围与重叠、完整解码、30 FPS 帧数、音视频起点／时长，并独立将成片抽样画面和原声与对应原片区间比对。回放使用事件关键时刻及其证据引用。

输出目录：

```text
run/
  event_timeline.json          # 共用事件、双维度、请求采样和未完成记录
  audio_events.json           # 本场背景归一化与声音事件假设
  collections_report.json
  collections/highlights/     # 独立清单、片段与成片
    verification[_lively].json            # 解码、帧数、音视频时间
    alignment_verification[_lively].json  # 原画面／原声内容对齐
  collections/bloopers/       # 同样生成两类校验报告
```

五佳球/十佳球由 `--top-k` 决定；趣味榜最多五段。素材不足输出实际数量和原因；零段只写报告，不生成空视频。小于五段时片头快切也使用实际数量。两榜、切换 top-k 和重复运行共用源身份、模型、提示词和采样配置匹配的事件缓存，`--no-analysis-cache` 强制新分析。

## 时限与验收

`--analysis-timeout` 现在是**每个源视频独立的事件分析预算**，默认 1800 秒。`match` 中每局启动自己的计时，不再共享从当天第 1 局开始的截止时间。因此四局的事件分析最多有四份预算，不能把它理解为整天 30 分钟的总时限。

`--review-budget-fraction` 默认 0.4：粗读最多使用 1080 秒，至少 720 秒留给复核。粗读的音频准备、声音推理、采样、API 请求和重试都使用粗读截止时间。粗读提前完成时，其未用预算也转入复核。复核计时在本地回合清单及粗读结果就绪后启动，包含复核证据准备与请求；等待较慢的本地推理不会耗掉这份保留时间。即使粗读全部超时，本地回合仍会获得复核机会。

每次 API 请求和重试使用当前阶段剩余预算与 `--api-timeout` 中较小的值，并在响应读取和下一次请求前检查绝对截止时间。阶段截止后停止排新请求，用已有证据生成报告。`urllib` 的连接超时和分段读取检查不是涵盖 DNS、连接建立及所有阻塞操作的进程级硬中断保证；声音推理等已启动的本地操作也需要安全结束，超出粗读预算的时间记录在 `phase_timing.coarse_overrun_sec`。因此事件预算并非整个命令的强制终止时间；本地清单等待、渲染和校验还会增加总耗时。

每局 `event_timeline.json` 的 `phase_timing` 记录粗读预算/耗时、等待清单时间、复核保留预算/实际预算/耗时，以及两个阶段是否到期。`budget_scope` 为 `per_source`。`timing_latest.json` 记录单视频命令总耗时，`match_summary.json` 记录当天命令总耗时；并发的本地推理和粗读耗时不可直接相加。

`analysis_status` 区分 `complete`（粗读和复核均完成）、`partial`（有成功请求但仍有失败或未处理项）、`failed`（无成功理解请求）和 `not_configured`。当天任意一局分析不完整时，`match_summary.json.status` 为 `analysis_incomplete`，不再显示 `collections_completed`。双榜报告同时保留分析状态：零事件且分析不完整只表示证据不足，不能据此断言整场没有精彩或趣味片段。零段不会渲染视频，也不会生成“校验通过”的记录。

可用 `scripts/probe_event_models.py` 在同一服务列出的模型之间比较相同真实区间的 2 FPS 粗读与 8 FPS 复核。脚本使用生产提示词、严格事件校验和有限单请求超时，保存输入帧数、用量、响应耗时、空事件及失败原因；仅上传抽样画面。选择模型前应先获得该录像向配置服务上传的授权，命令示例：

```bash
.venv/bin/python scripts/probe_event_models.py \
  --run runs/my-match/parts/set-0001 \
  --models glm-5.3-flash --reasoning-effort low \
  --start 1508 --end 1532 --width 224 --timeout 90 \
  --output runs/model-comparison
```

模型必须同时适合粗读和长上下文复核。一次 HTTP 200、合法空数组或非空预测均不足以证明识别准确性；检查响应内容和实际帧数后再通过 `--vision-model` 选择，避免仅凭模型名称自动替换。

修复失败任务后可用 `scripts/replay_event_failures.py` 按已有任务 ID 重放同一源视频、同一上下文；固定使用 `glm-5.3-flash`，独立新目录，不复用旧语义结果。它会重新上传采样画面及生产流程中的本地证据摘要，不上传 WAV；执行前仍须明确获得将这些资料发往当前配置服务的授权。该重放不是字节相同的历史请求：粗读使用已保存的全源声音事件及全局 ID，历史粗读使用块内事件列表及局部 ID；新的提示词与 wire Schema 也已变化。命令和产物说明见[脚本说明](../scripts/README.md#失败任务重放)。

按比赛划分 train/calibration/test，标注精彩和趣味事件源区间、期望剪辑边界，并由人工裁判标注入选质量和解释是否正确。运行：

```bash
python scripts/evaluate_events.py annotations_and_runs.json --output evaluation.json
```

输入字段见脚本模块说明。报告按比赛/榜单输出候选覆盖率、前五人工质量、解释正确率、剪辑完整性，以及同硬件、同输出规格、同缓存条件的端到端中位数/P95。未评审、未匹配和样本数量均显式保留。性能基线必须包含上传、排队、渲染与校验，不得只比较 API 时间。

已加入合成测试：静音和音量归一化、相机平移、短精彩/长普通回合、无关笑声引用、未知证据、疑似受伤、跨源去重、剪辑边界、一次复核与共享缓存。Actions 的公开回归还会构造 4 秒的测试画面和正弦原声，从趣味榜编排入口执行完整媒体校验，并要求产生 `alignment_verification.json`；这条回归只防止内容对齐检查再次从新入口脱落。真实比赛标注、真实音视频服务能力、PANNs 导出权重和硬件性能仍需现场验证；“较旧版增加不超过 25%”是优化目标，尚非实测承诺。

每场标注也可用 `"run_directory": "runs/match-events"` 替代 `predictions`，脚本会读取实际事件时间轴及两榜剪辑单，避免手工复制预测结果。
