# API 调用修复与复测

客户端的传输诊断、输出预算及视觉输入已修正。同一 AiHubMix 服务、同一 `gemini-3.1-pro-preview` 模型，最终四条视频请求均以 HTTP 200、完整 JSON、正常结束标记返回，耗时 27.3–35.4 秒。但配音内容验收尚未全部通过：一球仍误判重扣，另一球的配音位置与模型自己标注的触球冲突。不能把请求成功等同于自动配音正确。

## 修复与证据

- 复用此前回放实验成功使用的增量 SSE 读取方式，处理分块、换行、心跳、EOF、大小限制和总时限。分别记录连接、读取和解析阶段、底层异常类型、首字节时间、最终回答开始时间、HTTP 状态、结束原因和用量；不记录密钥或思考文本。
- 本轮第 2 次请求明确返回 `MAX_TOKENS`：并非连接失败，而是 8192 的输出预算被用完，最终 JSON 截断。默认预算改为 16384。失败结果不能补成成功，也不会自动重试。
- 中等推理强度的完整请求仍把救球误判为重扣；单帧中立描述却正确看到了低身、双脚着地的球员。因此不能归因为图像完全未送达。最终恢复高推理强度，同时突出目标参考帧、减少外围重复帧，只向模型发送已入库且未禁用的梗规则。
- 目标前后 0.6 秒保持密集取样，其余上下文约 0.25 秒一帧，保留边界与原始 PTS。最终四球共 97 张不同的本地准备帧，每个请求末尾再展示一次其目标帧，共发送 101 张图片。局部图像来自同一原始帧，全景始终保留；成片仍采用单画面。
- 拟使用“开炮”时新增独立动作复核：仅给模型目标前后的七张帧和中立观察问题，不发送先前答案或梗规则。只有两次判断均支持明确重扣才可进入计划。缺少复核、力度不明或判断矛盾时跳过。复核和主请求共享持久化总额度，均不自动重试。

最后一项的额度、缓存、失败拦截及矛盾拦截已通过离线测试，真实独立复核尚未发送，不能声称已验证其识别改善。两次模型判断一致也不等于动作事实必然正确。

此前两条 `connection_error` 的日志没有底层异常信息，无法追溯其确切原因。本轮没有服务端 5xx 的证据，不将那些旧失败直接归因于 AiHubMix 服务故障。

本次 API 修复任务实际发送 8 次请求；此前任务的账本未重置或修改。只使用已批准四球的抽样画面，未上传原视频或音频。
