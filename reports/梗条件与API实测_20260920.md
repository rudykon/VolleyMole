# 梗条件与 API 实测

这是首轮历史记录。后续客户端修复和八次诊断见 [API 调用修复与复测](API调用修复与复测_20260920.md)。

用户指出 9.8 第 3 球是吊球，不能配“开炮”，并要求为各梗设置条件、由大模型 API 判断何时配音。已完成 13 种梗的条件配置、API 选择阶段与修正版，但本轮真实 API 验证尚未通过。

## 已完成的改动

- 开炮须有充分挥臂、强力触球、至少三帧有序出球轨迹，并识别为明确重扣。吊球、轻拍、滚吊、二传、发球、救球、拦网及力度不明禁用。
- 全部 13 种梗配置各自的必需事实、可选事实、禁用事实、配音位置及保守置信度门槛；完整条件见[配置说明](../docs/梗使用条件与API导演.md)。模型的自报置信度不是校准后的可靠性保证。
- 模型读取原速时间戳画面，返回梗或跳过、引用证据、开始对应帧和触球帧；程序检查条件、映射回放时间、保护触球声、检查完整台词，再做全片密度控制。
- 四球最多两处，每球最多一处，梗不重复。允许零条；API 失败、矛盾或证据不足不会触发规则猜梗、换梗或强制补齐。
- 当前可播放素材仍只有 nice、开炮；其他 11 个规则已配置，素材尚未入库。

## 实际请求与限制

本轮只使用 AiHubMix 的 gemini-3.1-pro-preview，四个回合各调用一次，共发送 200 张原视频抽样 JPEG；不发送整段视频或音频，不对任何已失败回合重试。调用与前一轮回放诊断的记录分开，旧额度和记录未修改。

| 次数 | 回合 | 结果 | 处理 |
|---|---|---|---|
| 1 | 9.15 第 2 球 | 回答未通过领域结构校验；初版未保留失败原文，无法进一步确定具体字段 | 保留原声；补充精确错误码、脱敏失败原文及标签枚举 |
| 2 | 9.15 第 8 球 | 原生非流式请求连接异常 | 保留原声；剩余请求切换原生流式 |
| 3 | 9.8 第 1 球 | 结构有效，回答 skip；把目标动作描述为发球，与此前救球画面核验不符 | 不加梗；不能视为正确的动作识别 |
| 4 | 9.8 第 3 球 | 原生流式请求连接异常 | 保留原声；用户的吊球禁用条件仍有效 |

本轮 4 次上限已用完。三条失败请求的状态和账本保留不变；分支执行器绑定此前账本哈希，并在执行前后核对全轮总数不超过 4。没有将失败结果包装为有效的“无需配音”判断，也没有声称四球均通过 API 审核。

为后续验证增加 `focus_event_source_sec`，要求模型围绕目标触球判断，不能将上下文内另一动作当目标。流式配置已对齐此前成功的 `includeThoughts: true`，客户端丢弃思考片段，不存入结果或日志；这项传输调整的改善仍未验证，不能断言连接异常的具体成因。新的四球准备文件位于 `runs/meme-policy-20260920/api_next_prepared/`，本轮没有向它发送请求。
